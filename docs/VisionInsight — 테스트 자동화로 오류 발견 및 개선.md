# VisionInsight — 테스트 자동화로 오류 발견 및 개선

**기준일:** 2026-10-20  
**프로젝트:** VisionInsight (React/Vite + FastAPI + PatchCore + Gemini)  
**검증 대상 영상:** `VID-000003` — 16초 / 480프레임 / 30 fps / 1920×480 / H.264  
**자료의 성격:** 사용자 제공 Codex 실행 보고와 Chrome 확인 화면에 근거한 구현·검증 요약. 실제 Windows 파일·로그를 이 문서 작성 과정에서 재실행하거나 직접 재검증하지는 않았음.

---

## 1. 추진 배경과 목적

VisionInsight는 LiveView 영상에서 프레임을 선택하여 ROI를 지정하고 Grab 이미지를 검사하는 시연형 비전 검사 시스템이다. 화면 기능이 늘어나면서, 수정 후 기존 동작이 유지되는지 사람이 반복 확인하는 방식에는 한계가 있었다.

이를 개선하기 위해 **Gemini로 전체 E2E 테스트 시나리오 15개를 설계**하고, **Codex로 Playwright 읽기 전용 자동 테스트 5개 흐름을 구현**했다. 1단계에서는 실제 Capture/Inspection 생성이나 외부 Gemini API 호출을 하지 않는 검증을 우선했다.

- **Playwright 역할:** 실제 Chrome 조작, UI 상태·데이터 일치 검증, 실패 화면·로그 수집
- **Gemini Computer Use:** 향후 이미지 오버레이 정렬·문구 겹침 등 시각 검증 보강 계획. **현재 자동 실행에는 미연동**
- **운영 원칙:** `VID-000003`만 검사 영상으로 사용하고, 모델 OK/NG 결과를 임의로 가정하지 않음

## 2. 자동화 테스트 현황

| 흐름 | 검증 대상 | 가장 최근 확인된 상태 | 증거·해석 |
|---|---|---|---|
| TC-01 | 영상 재생·Pause·Seek·±1 Frame | **PASS** | 처음 발견된 프레임 왕복 오류 수정 후 실제 Chrome 재검증 |
| TC-02 | 검사 상위/하위 탭 전환 | **PASS** | 기존 검사 ID 유지, 탭 전환만으로 신규 분석 요청 없음 |
| TC-03 | Heatmap·Zoom·Pan·Reset·Pixel Inspector | **PASS** | 저장된 공개 검사 `INSP-001651`과 원본 PNG를 대조해 RGB/GV 확인 |
| TC-04 | 병 외곽/내부 림 Edge 표시 및 신뢰도 | **BLOCKED (미검증)** | 최초에는 소유 세션 부재로 SKIP, 신규 Capture 방식은 TTL 보존 게이트에서 실행 전 차단 |
| TC-05 | A~D 영역별 GV 및 계산 불가 처리 | **BLOCKED (미검증)** | TC-04와 동일 원인. Chrome 수동 확인과 자동화 검증을 구별해야 함 |

> **상태 해석:** 위 표는 개별 실행 결과를 종합한 최신 상태이며, 5개 테스트가 동일한 마지막 실행에서 3 PASS / 2 BLOCKED를 반환했다는 의미는 아니다. 초기 실행은 **2 PASS / 1 FAIL / 2 SKIP**이었다. TC-01 수정 후 해당 테스트는 별도로 PASS했고, 이후 TC-04·05 승인형 실행은 **BLOCKED**로 종료됐다.

## 3. 실제 발견한 오류와 수정 사례

### 사례 1 — ±1 프레임 왕복 후 프레임이 달라지는 오류 (**발견·수정·재검증 완료**)

| 구분 | 내용 |
|---|---|
| 발견 방식 | Playwright TC-01 실제 Chrome 자동 실행 |
| 재현 과정 | `VID-000003`의 120프레임에서 `+1 Frame` → `-1 Frame` |
| 기대 결과 | `120 → 121 → 120` |
| 실제 오류 | `120 → 121 → 119` |
| 원인 | Chrome의 시간 정밀도·절삭과 초 단위 증감, 프레임 인덱스 내림 계산이 겹침. 예: `3.999999초`가 119프레임으로 계산됨 |
| 개선 방법 | `LiveView.tsx`와 `videoFrames.ts`에서 정수 프레임 인덱스 중심으로 ±1 이동과 Seek 처리 통일. 실제 재생 시간은 대상 프레임 구간 안쪽으로 이동, Seek 완료 전 Grab 차단 |
| 재검증 | 실제 Chrome **TC-01 PASS**, `120→121→120` 및 0·479 경계, 재생·Pause 전환 확인. 관련 단위 테스트 **8 PASS** |
| 영향과 한계 | 표시 프레임과 Grab 대상 프레임이 어긋날 위험을 낮춤. 이번 수정은 실제 신규 Grab 검사로 검증한 것은 아님 |

**핵심 의미:** 기존 수동 점검에서 놓칠 수 있는 **1프레임 오프바이원(off-by-one) 오류**를 자동화가 재현하고, 수정 후 같은 테스트로 회귀 검증했다.

### 사례 2 — 기존 Grab Crop의 소유 세션이 없어 Edge/GV 자동 검증 불가 (**기능 오류 아님 / 해결 보류**)

| 구분 | 내용 |
|---|---|
| 증상 | TC-04·TC-05가 SKIP됨 |
| 확인된 원인 | Playwright는 별도의 Chrome 컨텍스트에서 실행되어 `INSP-001694`의 원래 Capture 소유 세션이 없음 |
| 대체 확인 | 공개 저장 검사 `INSP-001651`은 조회 가능했으나 정적 이미지이므로 Grab 전용 Edge 버튼이 비활성화됨 |
| 적절한 처리 | 검사 출처를 Grab으로 위장하거나 소유권 검증을 우회하지 않고 **SKIP** 처리 |
| 개선 방안 | `VID-000003`에서 정상 세션으로 Grab 1회를 생성하고 같은 브라우저 컨텍스트에서 Edge/GV 검증하는 승인형 테스트 별도 설계 |
| 검증 상태 | 해당 흐름은 **아직 자동화 PASS 아님**. 원래 사용자 Chrome에서는 Edge/GV 상세 화면이 수동으로 확인됨 |

### 사례 3 — Capture TTL 정리로 기존 PNG가 삭제될 수 있는 위험 (**실행 전 차단 / 개선 보류**)

| 구분 | 내용 |
|---|---|
| 발생 단계 | 위 사례 2를 해결하려고 Capture 1회 생성형 Playwright 실행기를 준비한 단계 |
| 발견 위험 | 정상 Capture 세션 발급 과정에서도 `bootstrap → cleanup`이 동작해 오래된 PNG를 삭제할 가능성 |
| 관찰 | 기존 Capture PNG 2개는 확인 당시 생성 약 41분 경과, 기본 TTL은 30분. 실행 서버의 정확한 만료 시각은 미확인 |
| 안전 조치 | 보존 게이트에서 신규 세션 발급과 Grab을 차단. **세션 POST 0회 / Grab 0회**, 기존 PNG와 검사 기록 유지 |
| 구현·검증 | 승인형 실행기와 최대 Grab 1회 제한 추가, 안전 정책 단위 테스트 **5 PASS**, 실제 E2E는 **BLOCKED** |
| 후속 해결 계획 | **발표 이후 이번 주**, 기존 운영 서버·데이터를 그대로 두고 빈 Capture 디렉터리의 **격리 테스트 서버**를 구성하여 TC-04·05 검증. 별도 환경 구성 및 실행은 그때 승인 후 진행 |

> **발표 시 표현 주의:** 사례 3은 실제 데이터 삭제 사고가 아니라 **자동화 사전 검증에서 발견한 삭제 위험을 방지한 사례**다. TC-04·05는 버그 검출 실패도, 기능 검증 PASS도 아니며 **데이터 보호 때문에 자동 실행을 보류한 상태**다.

## 4. 실행·검증의 증거

- 기본 읽기 전용 E2E 실행: `frontend`에서 `npm.cmd run test:e2e:readonly`
- 프레임 버그 수정 회귀: `npm.cmd run test:e2e:readonly -- --grep TC-01`
- TC-04·05 접근 가능성 검사(신규 Grab 없음): `npm.cmd run test:e2e:readonly -- --grep "TC-0[45]"`
- 승인형 Capture E2E 실행기는 코드가 추가됐으나 **TTL 보존 게이트에서 차단**되어 신규 Capture·Inspection을 만들지 않음
- 테스트 스크린샷·로그(사용자 제공 Codex 보고 경로):
  - 최초 읽기 전용 테스트: `data/outputs/playwright-readonly/2026-10-19T17-17-43-850Z-4279ad66/`
  - TC-04·05 접근성 검사: `data/outputs/playwright-readonly/2026-10-19T17-32-55-429Z-fcbdc2e8/`
  - Capture 보존 게이트 차단: `data/outputs/playwright-capture-edge-gv/2026-10-19T17-48-22-111Z-6f97d80a/`

**검증 경계:** Chrome 화면에서 수동으로 확인된 `VID-000003` 영상, Edge, 영역별 GV와 Playwright에서 자동 PASS 판정된 범위를 구분해야 한다. Gemini Computer Use 시각 브리지는 아직 구현·실행되지 않았다.

## 5. 발표용 PPT 슬라이드 구성안

### 슬라이드 A — 테스트 자동화로 실제 버그를 찾아 수정

**슬라이드 제목:** `Playwright E2E — 실제 오류 발견과 회귀 검증`

- **배경:** Gemini 시나리오 15개 설계 → Playwright 읽기 전용 5개 흐름 구현
- **발견:** `120 → +1 → -1` 후 **119프레임**으로 복귀하는 시간↔프레임 변환 오류
- **수정:** 정수 프레임 기준 Seek/이동 통일, Seek 완료 전 Grab 차단
- **검증:** 실제 Chrome TC-01 **PASS**, 경계 프레임 0·479 검증, 단위 테스트 **8 PASS**

**시각 구성:** `오류 120 → 121 → 119` (붉은색) vs `개선 120 → 121 → 120` (초록색) 좌우 비교. Playwright 실패/성공 화면 또는 테스트 로그 스크린샷이 실제로 존재한다면 첨부해 사용.

**발표 대본 (약 30초):**
> “기능 구현 후 수동 시연뿐 아니라 Playwright를 통한 실제 Chrome 자동화 검증을 도입했습니다. 그 과정에서 120프레임에서 한 프레임 앞으로 이동했다가 되돌아오면 119프레임이 표시되는 오류를 재현했습니다. 시간 계산을 정수 프레임 중심으로 수정하고 탐색 중 Grab도 제한했습니다. 같은 E2E 테스트와 프레임 경계 테스트로 수정 효과를 확인했습니다.”

### 슬라이드 B — 자동화 검증 범위와 안전한 후속 계획

**슬라이드 제목:** `자동화 테스트 현황 및 데이터 보호 기반 검증 계획`

- **검증 현황(누적 최신 기준):** 3개 PASS, Edge/GV 2개는 **BLOCKED** (자동 검증 미완료)
- **PASS:** 영상·프레임 조작 / 탭 전환 / Heatmap·Zoom·Pixel Inspector
- **BLOCKED 원인:** 새 브라우저와 기존 Grab 사이 **Capture 세션 소유권 차이**
- **데이터 보호:** 만료된 Capture PNG의 삭제 가능성을 발견해 신규 Grab을 **실행 전 차단** — 삭제 사고 없음
- **이번 주 개선:** 기존 서버와 분리된 빈 Capture 저장소를 사용하는 테스트 환경 구성 → TC-04·05 자동 검증

**시각 구성:** `3 PASS / 2 BLOCKED` 현황 + `기존 서버(보존) / 격리 테스트 서버(예정)`의 두 갈래 도식. **BLOCKED를 FAIL 또는 PASS로 바꿔 표현하지 않기.**

**발표 대본 (약 30초):**
> “현재 읽기 전용 자동화 흐름 5개 중 3개 기능을 검증했고, Edge와 영역별 밝기 2개는 자동 검증 대기 상태입니다. 기능이 고장 난 것이 아니라 기존 Grab 이미지의 세션 소유권 때문에 별도 브라우저에서 접근할 수 없었습니다. 또한 테스트용 Capture 생성 과정에서 오래된 파일이 정리될 위험을 미리 발견해 실행을 차단했습니다. 발표 이후 이번 주에는 격리된 테스트 환경에서 남은 두 흐름을 검증할 계획입니다.”

**권장 삽입 위치:** VisionInsight **실제 검사 시연 결과 다음**, A·B·C 검출력 개선 계획 **직전**. 기술적 성과 → 자동화 검증 및 개선 → 다음 개발 계획 순서.

| **발표 전** | `VID-000003` 시연 동선 및 기존 저장 결과 확인 | 영상→Pause→ROI→Grab 관련 버튼 상태 확인; LIVE Google 재호출은 필수 아님 |

### 발표 문구에서 피할 표현

- “자동화 테스트 5개 전부 통과” → **아님: 3개 확인, 2개 자동 검증 보류**
- “Edge/GV 검출 정확도 입증” → **아님: 표시 및 영역 통계는 수동 확인, 자동 회귀 일부 대기**

- “Gemini Computer Use로 자동 검증 완료” → **아님: 시나리오 설계 완료, Playwright 중심 실행**
- “검출률 향상 검증 완료” → **아님: 라벨 기반 정량 성능 평가는 후속 과제**
