# VisionInsight 이미지 검사 검출력 보강 방안

**A. 배경·밝기·화질 영향 완화   |   B. 영상 도메인 정합성 강화   |   C. 보조 검사 결합**

> **문서 목적**  
> 현재 관측된 현상과 검증되지 않은 개선 가설을 구분해, 실제 신규 Grab 이미지의 검사 품질을 높이기 위한 실험·구현 방향을 정리한다.

## 핵심 결론

지금 필요한 것은 단일 숫자 임계값 변경이 아니라, 품질 평가의 타당성, 학습·평가 데이터의 대표성, 결함 신호의 다중 확인을 함께 개선하는 것이다.

| 구분 | 현재 관측된 문제 | 우선 실행 방향 |
| --- | --- | --- |
| A · 밝기/화질 | ROI 전체 평균 GV가 병·배경 구성에 영향을 받으며, LiveView Grab이 원본보다 흐릿하게 보이는 사례가 있음 | 전경/배경·노출·선명도 지표를 분리하고 원본→영상→Grab→표시 과정의 화질 손실 비교 |
| B · 도메인 | 정적 MVTec 영상과 실제 LiveView Grab의 조명·크기·배경 차이 | 정상/불량 Grab 검증셋 구축, 오검·미검 측정 |
| C · 보조 규칙 | Heatmap이 배경에서도 붉게 반응하며 빨강 ≠ 결함 확정 | 기하학적·시각적 증거를 보조지표로 교차 검증 |

### 현재 확인된 사실과 주의점

- 기존 품질 평가는 ROI 전체의 평균 회색조 값(GV)을 사용하며, 현재 운영 안내 하한은 125.0이다. 이 수치는 업계의 보편 기준이 아니라 현재 구현의 기준이다.

- PatchCore 이상 점수 임계값은 34.1442이며, 모델의 OK/NG 소견과 서버의 최종 OK/NG/REINSPECT는 별개이다.

- 실제 Grab에서 평균 GV 120 전후로 WARNING_LOW_BRIGHTNESS → REINSPECT가 관측되었으며, NORMAL/OK로 완료된 검사 사례도 확보했다.

- 정적 원본 병 이미지와 LiveView Grab을 비교했을 때 Grab의 병 림·표면 세부가 더 흐릿하게 보이는 사례를 확인했다. 원인이 동영상 합성, 리사이즈, 인코딩, 프레임 추출, 실제 초점 또는 뷰어 확대 중 어느 단계인지 정량 검증하지 않았다.

- Heatmap의 배경 붉은 반응은 원본 이상지도 값에 존재하고, 영상별 min-max 정규화로 시각적으로 강조된다. 좌표 불일치나 PNG 생성 오류는 확인되지 않았다.

> **원칙**  
> 원본 검사 기록·서버 최종 판정·현재 임계값을 근거 없이 변경하지 않는다. 16초짜리 합성/편집 영상의 OK·NG 장면은 데모 자료이며, 독립 검증을 거치기 전 실제 검출력의 근거로 사용하지 않는다.

*A  /  IMAGE QUALITY*

## 배경·밝기 영향 줄이기

**밝기 경고가 실제 결함과 무관한 환경 차이를 과도하게 반영하는지 데이터로 확인한다.**

### A-1. 왜 필요한가

기존 정적 정상 이미지(예: 900×900, 밝은 배경)와 LiveView Grab Crop은 배경 밝기, 병 크기, 시점, 주변 여백이 다르다. ROI 전체 평균 GV는 병의 어두운 내부와 밝은 배경을 한 번에 평균하므로, 제품이 같아도 배경 비율과 Crop 위치에 따라 수치가 달라질 수 있다.

### A-2. 권장 보강

| 세부 과제 | 측정·검토 내용 | 주의점 |
| --- | --- | --- |
| ROI 구성 측정 | 병이 차지하는 면적 비율, 병 중심 위치, Crop 주변 여백 기록 | 고정 ROI 보정은 비교 실험 후 판단 |
| 영역별 밝기 | 기존 전체 GV + 병 전경 GV + 배경 GV + 전경/배경 대비를 나란히 산출 | 병 내부는 본래 어두우므로 전경 GV만으로 판정하지 않음 |
| 촬영 품질 분리 | 포화 픽셀 비율, 흐림, 그림자·반사광 등 품질 지표 실험 | 결함으로 인해 생긴 변화와 촬영 오류를 구분 |
| 품질 기준 재검토 | NORMAL/경고 Grab 샘플의 지표 분포, 오경보·미경보를 비교 | 125.0을 단순 하향 조정하지 않음 |

### A-3. 권장 오프라인 실험

- 동일 병의 프레임·ROI에 대해 기존 전체 GV, 병 전경/배경 GV, 대비, 흐림 정도를 함께 저장하고 비교한다.

- 명확한 양품과 실제 저품질 사례를 사람의 육안 기준으로 먼저 분류한 뒤, 현재 경고가 어떤 사례를 잘못 분류하는지 확인한다.

- 후보 품질 규칙을 기존 규칙과 병렬 실행하여 OK/REINSPECT/NG 비율과 미검 위험을 비교한다. 사용자 동의 없이 운영 판정에는 적용하지 않는다.

> **성공 기준**  
> 이미지 밝기 경고의 불필요한 REINSPECT는 줄이면서도, 실제 흐림·과노출·반사·잘림 등 위험 사례가 NORMAL로 누락되지 않아야 한다.

### A-4. LiveView Grab 화질·선명도 개선 (이번 주 구현·검증 목표)

**현상:** 기존 고해상도 정적 병 이미지와 비교하면 실제 LiveView Grab Crop에서 림의 미세 윤곽, 표면 질감, 작은 결함 후보가 흐릿하거나 뭉개져 보이는 사례가 있다. 특히 작은 크랙·칩핑·이물 신호가 입력 단계에서 소실되면 이후 모델이나 UI 확대만으로 복구할 수 없다.

**현재 확정되지 않은 원인:** 초점 불량이라고 단정할 수 없다. 원본 정적 이미지와 합성 영상은 이미지 생성·크기 변경·압축·Crop·표시 과정이 다르므로, 화질 저하가 **원본 소스 → 합성·편집 → H.264 인코딩 → 디코딩·Grab → Crop 저장 → 뷰어 확대** 중 어디서 발생하는지 분리해야 한다.

| 개선 과제 | 비교·검증 방법 | 완료 판단 기준 |
| --- | --- | --- |
| 원본과 Grab 해상도 추적 | 원본 픽셀 크기, 영상 속 병의 실제 픽셀 크기, 저장 Crop 크기, 모델 입력 리사이즈 경로 확인 | 축소·보간 단계와 정보 손실 위치 확인 |
| 인코딩/합성 영향 점검 | 같은 장면의 인코딩 전 프레임, MP4 디코딩 프레임, 저장 Crop을 정렬해 비교 | 인코딩 과정에서 작은 결함이 손실되는지 근거 확보 |
| 선명도 수치화 | 병 림 영역에서 경계 강도·흐림 지표(예: 라플라시안 분산) 비교, 동일 위치 육안 판정 병행 | 상대적인 흐림 정도 재현 가능하게 기록 |
| ROI 및 표시 최적화 | 병의 프레임 내 점유 픽셀 증가 가능성, 확대 시 보간법, 원본 비율 유지 검토 | 표시만 확대하는 작업과 실제 입력 개선을 구분 |
| 작은 결함 검출 검증 | 동일 결함의 원본·영상·Grab 쌍으로 PatchCore 점수 및 결함 가시성 비교 | 독립 라벨 기준 미검·오탐 변화를 확인 |

**안전한 적용 원칙:** 우선 데이터 변경 없는 오프라인 비교를 실시한다. 화면의 `Fit to View` 같은 확대는 **사용성 개선**일 뿐 검출력 개선으로 간주하지 않는다. 영상·전처리 변경은 동일 샘플의 결함 가시성과 FN/FP 비교 결과가 있을 때만 단계적으로 적용한다. 기존 Crop, 검사 기록, PatchCore 임계값과 서버 판정 정책은 근거 없이 변경하지 않는다.

> **이번 주 목표(계획, 구현 완료 아님)** ① 화질 손실 단계 재현·정량 비교 → ② 최소한의 영상/Grab 개선 후보 실험 → ③ 동일 원본의 전후 시각화와 평가 결과 기록. 작은 결함 검출률 향상이나 완료 일정은 검증 전 보증할 수 없다.

*B  /  DOMAIN ALIGNMENT*

## 학습 데이터와 실제 Grab 환경 맞추기

**PatchCore의 판정력은 모델 구조뿐 아니라 정상 데이터가 실제 검사 환경을 얼마나 대표하는지에 달려 있다.**

### B-1. 왜 필요한가

정적 MVTec 기반 입력과 컨베이어 LiveView의 해상도, 병 크기, 밝기, 반사, 방향, 배경이 다르면 정상 병도 높은 이상 점수로 나올 수 있다. 반대로 실제 결함이 기존 학습 분포와 구분되지 않아 미검될 가능성도 있으므로, 우선 현 영상 도메인에 대한 성능을 측정해야 한다.

### B-2. 데이터셋 보강

| 데이터 분류 | 수집 목적 | 라벨 기준 |
| --- | --- | --- |
| 정상 Grab | 정상 변동(조명·위치·병 방향) 범위 파악 | 사람이 확인한 실제 양품, 원본 영상/프레임 추적 |
| 불량 Grab | 파손·이물·변형 등 유형별 검출 가능성 확인 | 결함 위치·종류가 확인된 독립 샘플 |
| 저품질/경계 | 품질 경고와 결함 판정의 혼동 분리 | 조명/흐림/잘림 등 품질 원인 별도 표기 |
| 합성 데모 영상 | UI·그랩 동작·시연 시나리오 확인 | 시각적 데모 라벨, 실제 성능 검증 라벨과 분리 |

### B-3. 평가 방법

- 동일 물리적 병 또는 같은 원본 영상의 연속 프레임이 학습셋과 평가셋에 동시에 들어가지 않게 분리한다. 데이터 누수를 예방하기 위해 병/영상 단위로 묶어서 분할한다.

- 현재 PatchCore를 먼저 고정한 상태에서 혼동행렬(TP/FP/TN/FN), 불량 Recall, 양품 오경보율(FPR), Precision을 산출한다.

- 모델 점수의 ROC/PR 분포와 결함 유형별 성능을 확인한다. 샘플 수가 적으면 신뢰 구간과 미확정 사항을 명시한다.

- 정상 Grab 추가 학습·적응 또는 임계값 재보정은 별도 실험으로 진행하며, 기존 모델 34.1442 임계값과 같은 평가셋에서 직접 비교한다.

> **실무 주의**  
> 정상 이미지 20~50장은 분포를 탐색하는 파일럿에는 유용하지만 검출력이나 안전성을 입증하기에는 부족할 수 있다. 실제 불량 사례를 포함한 독립 검증이 필요하다.

### B-4. 성공 기준

같은 독립 평가셋에서 불량 미검(FN)을 악화시키지 않으면서 정상 오경보(FP)를 줄이거나, 동일한 오경보 수준에서 불량 Recall을 올리는 것이다. 단순히 데모 영상의 OK 비율을 높이는 것은 검출력 개선으로 간주하지 않는다.

*C  /  SECONDARY CHECKS*

## 모델 외 보조 검사 결합

**PatchCore를 대체하지 않고, 결함 종류별로 독립적인 근거를 추가해 판정의 해석 가능성을 높인다.**

### C-1. 병 영역 분리와 Heatmap

현재 Heatmap은 ROI 전체 영역의 PatchCore 이상도를 색상화하며, 흰 배경 모서리에서도 반응한다. 이는 정규화된 상대 색상이지 결함 확정 지도가 아니다.

- 실험: 병 윤곽 분할의 안정성을 측정한 뒤 병 내부/림/배경 영역별 이상도 통계를 별도로 산출한다.

- 원본 PatchCore 점수와 원본 Heatmap은 그대로 저장·표시하고, 마스크 기반 결과는 보조 정보로 병렬 제공한다.

- 배경 반응을 단지 없애 보이게 하기 위한 시각적 마스킹은 금지한다. 배경 결함 단서가 사라지는지 확인해야 한다.

### C-2. OpenCV 기하학적 보조 검사

| 검사 항목 | 방법 예시 | 주의점 |
| --- | --- | --- |
| 림 원형도 | 외곽·내곽 원 피팅, 편심, 원형도 편차 | 시점 왜곡·반사로 인한 가짜 변형 가능 |
| 입구 균형 | 림 두께 균일도, 중심 간 거리, 비대칭 | ROI 중심 정렬 및 회전·스케일 보정 필요 |
| 파손·칩핑 | 림 경계선 끊김, 국부 곡률 이상 | 조명 반사와 파손을 구분하는 검증셋 필수 |
| 오염·이물 | 색/질감의 국부 변화, 이물 후보 영역 | 검은 병 내부·그림자에 대한 오탐 주의 |

### C-3. Gemini Vision Judge와 결합

Gemini Vision Judge는 실제 Grab 이미지를 읽고 독립적인 OK/NG/REINSPECT 의견과 관찰 근거를 제시한다. 이미 Gemini Flash 실호출 성공 사례가 있지만, 이는 모델의 검사 정확도 검증과는 별개이다.

- Gemini 의견을 PatchCore 이상 점수, 영상 품질, OpenCV 보조 계측과 분리 기록한다.

- 서버 최종 판정과 3회 재검사/작업자 수동 확인 정책은 변경하지 않는다.

- 상충 사례(예: 서버 REINSPECT, Gemini OK)는 작업자 참고자료로 사용하고, 임의로 자동 OK 전환하지 않는다.

> **권장 방식**  
> PatchCore = 이상 패턴 탐지 / OpenCV = 계측 가능한 형상·촬영 품질 / Gemini = 시각적 설명 및 독립 의견. 어느 하나도 실제 물리적 정상·불량을 단독으로 확정한다고 과장하지 않는다.

> **발표 스크립트**
