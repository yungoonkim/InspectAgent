# A-2 최소 개선안 — 미구현·승인 대기

전제: [A-1 실측 기준선](a1-image-quality-baseline-analysis.md). 이 문서는 운영 품질 규칙의 변경 승인이 아니다.
현재125~150, PatchCore34.1442, 품질 경고→REINSPECT 우선 및 기존 데이터·수동 확인 정책을 유지한다.

## 우선 후보

| 우선 | 최소 후보 | 기대 효과 | 부작용·실패 처리 | 필요한 평가 데이터 | REINSPECT 영향 |
|---|---|---|---|---|---|
| 1 | 서버 검증 Grab 출처에만 기존 ROI 통계와 별도의 shadow 영역 통계 추가 | 배경 비율 때문에 mean이 변한 원인을 가시화 | 반사/잘림/흰 내부에서 분할 오류. 실패 시 null. 마스크를 정답 취급하지 않음 | 수동 마스크, 같은 병/노출에서 다른 배경·ROI 여백, 병 위치/크기/색의 독립 표본 | 초기 영향0. 기존 mean·품질 상태 보존 |

## 승인 전 최소 평가 계획

1. 제품의 정상/불량과 별도로 촬영 정보가 검사에 충분/불충분/판단 보류인지 정의한다. 평가자 사이의 불일치도 보존한다.
2. 같은 병·고정 ROI/스케일에서 노출·조명·초점·움직임·배경/여백을 각각 바꾼 대조를 승인 범위에서 확보한다. 이번 승인은 새 Grab/촬영/모델 실행을 포함하지 않는다.
3. 같은 물리적 제품·동일 영상의 인접 프레임이 학습/조정/평가에 섞이지 않게 그룹 단위로 분리한다.
4. 마스크 유효율, 판단 보류율, 촬영 품질 라벨에 대한 오수락/오경고 및 노출/해상도/배경/속도별 결과를 보고한다. 제품 결함 Recall과 혼동하지 않는다.
5. 같은 ROI의10px 확장 민감도, 분할 실패 처리, mean125/150 경계, NaN/Infinity/빈 이미지/손상 입력을 평가한다.
6. 등록 정적 이미지는 기존 경로를 보존한다. Grab 전용 profile의 타당성이 검증되면 서버 검증 provenance로 선택하며 클라이언트 임의 플래그는 신뢰하지 않는다.
7. shadow 단계는 기존 JSONL 과거 행을 바꾸지 않고 별도 분석 영역에 기록한다. 운영 schema 추가가 필요하면 변경 계약을 먼저 승인받는다.

## 구현을 시작하지 않을 항목

- 병 영역 mean에125를 그대로 쓰지 않는다. A-1 영역 mean 약60~70은 기존 전체 ROI 환경 기준과 다르다.
- 이번 세 이미지만 통과시키는 threshold, 배경 면적을 늘리는 유도, 기존 WARNING 무시는 구현하지 않는다.
- 과거 quality/final_result, RIG, 수동 확인, Gemini 결과를 재판정·덮어쓰기하지 않는다.
- 새 profile/경고가 생겨도 경고→REINSPECT 등 최종 결정층은 별도의 명시적 승인 없이 바꾸지 않는다.
- 적용 전 데이터·수락 기준·회귀 결과를 보고하고 사용자 승인을 기다린다.
