# VisionInsight 발표 시연 대본 (3~5분 라이브 데모)

- **작성일자:** 2026-10-19
- **발표 예정일:** 2026-10-20
- **목표 시간:** 3분 ~ 5분
- **시연 환경:** 브라우저 (`http://localhost:5173`), 백엔드 (`http://127.0.0.1:8000`)
- **발표 원칙:** "완성된 기능은 자신 있게 보여주고, 안전 게이트나 오프라인 상태인 기능은 기술적 이유와 함께 정직하게 설명한다."

## 0. 시연 전 체크리스트 및 준비 상태 점검 (발표 10분 전)

| 점검 항목 | 정상 상태 확인 기준 | 이상 시 조치 방법 |
| :--- | :--- | :--- |
| **1. 백엔드 서버** | `http://127.0.0.1:8000/docs` 접속 가능, Uvicorn 단일 워커 실행 중 | 백엔드 터미널 확인 (재시작 시 Capture 삭제 주의) |
| **2. 프론트엔드 서버** | `http://localhost:5173` 접속 가능, Vite 프록시(`/api`) 정상 바인딩 | `npm run dev` 실행 확인 |
| **3. 브라우저 세션** | 개발자 도구(F12) Network 탭에서 `POST /api/capture-sessions` (200 OK) 확인 | 화면 새로고침(F5) 1회 수행 |
| **4. 백업 데이터 준비** | 과거 검사 숏컷 버튼(`[T01:OK]`, `[T03:Warn]`, `[T06:한계OK]`, `[Mock:NG]`) 정상 표시 | 숏컷 클릭하여 카드 렌더링 사전 확인 |

## 1. 7단계 실시간 시연 흐름 요약표

```
[1단계: LiveView] ──> [2단계: Grab & 검사] ──> [3단계: 결과 & 히트맵]
       │                       │                         │
컨베이어 병 선택         무손실 Crop 생성           점수, 조도, Anomaly Map
       ▼                       ▼                         ▼
[4단계: 감사 추적] ──> [5단계: AI 보고서]  ──> [6단계: Vision 분석] ──> [7단계: 작업자 수동확인]
       │                       │                         │                       │
INSP-ID / 로그         Gemini Function Calling     Crop 원본 2차 소견        3회 상한 후 HOLD
```

## 2. 단계별 상세 시연 대본

---

### [1단계] LiveView에서 병 선택 및 ROI Grab (소요: 30초)

- **발표자 멘트:**
  > "먼저 실제 컨베이어 벨트에서 이송되는 병 영상을 확인하겠습니다. 상단 LiveView 플레이어를 보시면 1920×480 해상도의 고속 영상이 스트리밍되고 있습니다. 병이 검사 영역을 통과할 때 `[Pause]`를 누르고, 검사할 병 영역에 마우스로 드래그하여 직사각형 ROI를 지정합니다."
- **실행할 UI 동작:**
  1. LiveView 재생 중 `[Pause]` 버튼 클릭 (동영상 일시정지).
  2. 비디오 캔버스 위에서 마우스 드래그로 병 전체를 감싸는 직사각형 박스 설정.
- **기대되는 실제 화면:**
  - 동영상이 멈추고 붉은색 ROI 박스와 좌상단 좌표/크기 태그(예: `x=700, y=120, 284×272`)가 표시됨.
- **성공 판정 기준:**
  - 화면 버벅임 없이 즉시 일시정지되고 ROI 영역이 선명하게 활성화됨.
- **실패 시 안전한 대안 (Fallback):**
  - 만약 비디오가 재생되지 않거나 ROI 드래그가 먹히지 않을 경우:
    - *"LiveView의 실시간 스트림 대신, 사전에 캡처된 프레임 탭(`ImageView` 상단 Capture 소스)으로 전환하여 무손실 캡처 프레임을 보여드리겠습니다."*

### [2단계] 새로운 Crop 이미지로 실제 검사 트리거 (소요: 30초)

- **발표자 멘트:**
  > "이제 우측 패널의 `[Grab & Inspect]` 버튼을 클릭하겠습니다. 이 한 번의 클릭으로 브라우저는 백엔드로 프레임 캡처를 요청하고, 백엔드는 원본 영상에서 픽셀 손실 없이 ROI 영역을 잘라내어 고유 SHA256 해시를 부여한 뒤 검사 파이프라인으로 전달합니다."
- **실행할 UI 동작:**
  1. 우측 패널 상단의 `[Grab & Inspect]` 버튼 클릭.
  2. 로딩 스피너 및 진행 상태 확인.
- **기대되는 실제 화면:**
  - 신규 검사 ID(예: `INSP-001653` 등 순차 단조 증가 번호)가 발급되며 검사 패널과 중앙 600×600 뷰포트에 잘라낸 병 이미지가 로드됨.
- **성공 판정 기준:**
  - `POST /api/videos/{video_id}/grab` (201 Created) 및 `POST /inspections` 연속 성공.
- **실패 시 안전한 대안 (Fallback):**
  - 만약 네트워크 오류나 401 오류가 발생할 경우:
    - *"현재 개발 세션의 쿠키가 만료된 경우입니다. 이미 완벽하게 실행되어 데이터베이스에 보존된 실제 Grab 검사 기록인 `INSP-001652`를 불러와 검증하겠습니다."*
    - (과거 검사 ID 입력란에 `INSP-001652` 입력 후 로드)

---

### [3단계] 검사 점수, 영상 품질, Anomaly Heatmap 확인 (소요: 45초)

- **발표자 멘트:**
  > "검사 결과가 나왔습니다. 중앙 뷰포트의 판정 카드를 보시면 최종 판정은 **`REINSPECT` (재검사)**입니다. 여기서 매우 중요한 점이 있습니다. PatchCore 모델의 이상 점수는 `40.16`으로 고정 임계값 `34.14`를 넘어 모델 단독 소견은 `NG`였습니다.  
  > 하지만 상단 품질 지표를 보시면 평균 조도가 `59.76`으로 정상 기준 하한인 `125.0`에 미달했습니다. 컨베이어 벨트 배경이 어두워 조도 경고가 뜬 것입니다. 저희 판정 엔진은 조명 저하 상태에서 섣불리 제품을 폐기하지 않고 `REINSPECT`로 우선 분류했습니다.  
  > 또한 좌측 상단의 `[Heatmap Overlay]`를 켜면 모델이 256×256 임베딩 공간에서 이상 반응을 보인 부위가 Jet 컬러맵으로 겹쳐 보입니다."
- **실행할 UI 동작:**
  1. 검사 결과 카드에서 `anomaly_score` (`40.16`), `threshold` (`34.14`), `image_quality_status` (`WARNING_LOW_BRIGHTNESS`) 수치 포인팅.
  2. `[Heatmap Overlay]` 토글 스위치 켜기.
  3. 마우스 휠로 뷰포트 확대하여 4000% Cursor-Anchored Zoom 및 픽셀 격자 시연.
- **기대되는 실제 화면:**
  - 주황색/황색 `REINSPECT` 배지 선명하게 표시.
  - 병 뷰포트에 반투명 붉은색/푸른색 히트맵 오버레이 중첩.
  - 3200% 이상 확대 시 각 픽셀 셀 내부에 정수 Gray Value(0~255) 숫자가 실시간 표시됨.
- **성공 판정 기준:**
  - 모델 NG와 품질 Warning의 결합 결과가 결정론적 규칙에 따라 `REINSPECT`로 정확히 표시됨.
  - 히트맵을 켜도 하단 Pixel Inspector의 RGB 측정값은 원본 픽셀 값을 100% 무손실 유지.

### [4단계] Inspection ID 및 이벤트 로그 감사 추적 확인 (소요: 30초)

- **발표자 멘트:**
  > "하단의 실행 로그 타임라인을 확인하겠습니다. 발급된 고유 번호 `INSP-001652` 아래에 `INSPECTION_STARTED`, `IMAGE_LOADED`, `ANALYSIS_COMPLETED`, `INSPECTION_COMPLETED` 이벤트가 밀리초 단위 타임스탬프와 함께 기록되어 있습니다.  
  > 모든 검사 이력은 Append-only JSONL 파일에 즉시 영구 저장되므로, 공정 감사 시 단 하나의 검사도 누락되지 않고 역추적할 수 있습니다."
- **실행할 UI 동작:**
  1. 하단 `Execution Logs` 아코디언 확장.
  2. 4단계 생명주기 이벤트와 소요 시간(ms) 확인.
- **기대되는 실제 화면:**
  - 단계별 순차 로그 리스트가 초록색/파란색 아이콘과 함께 깔끔하게 나열됨.
- **성공 판정 기준:**
  - `GET /inspections/{id}/logs` 응답 데이터가 테이블 또는 타임라인 형태로 표시됨.

### [5단계] Gemini Diagnostic Agent의 근거 기반 보고서 확인 (소요: 45초)

- **발표자 멘트:**
  > "이제 우측 하단의 `[Gemini AI 진단 보고서]`를 보겠습니다. 에이전트는 환각(Hallucination) 없이 시스템 도구 4개를 실행하여 수집한 사실만을 바탕으로 보고서를 작성했습니다.  
  > 관측 사실(Observed Facts)을 보시면 '평균 밝기 59.76이 기준치 125.0보다 낮다', '모델 이상 점수는 40.16이다'라는 수치가 시스템 로그의 JSON 포인터와 1:1로 일치합니다.  
  > 에이전트는 이를 바탕으로 '카메라 조명 저하로 인한 오탐 가능성'이라는 가설을 세우고, 권장 조치로 `LIGHTING_EXPOSURE_CHECK`와 `MANUAL_REINSPECTION`을 제시했습니다. 하지만 가장 중요한 것은 에이전트가 서버의 최종 판정인 `REINSPECT`를 마음대로 바꾸지 못했다는 점입니다."
- **실행할 UI 동작:**
  1. 우측 패널의 `Gemini AI Diagnostic Report` 섹션 확인.
  2. 관측 사실(Observed Fact) 클릭하여 근거 데이터 앵커링 툴팁 시연.
- **기대되는 실제 화면:**
  - Fact 목록, Hypothesis 설명, Recommended Actions 배지 정갈하게 표시.
- **LIVE 미연결 시 대체 설명:**
  - 만약 외부 네트워크 차단으로 신규 API 생성이 어려운 환경일 경우:
    - *"실제 산업 현장의 보안 폐쇄망을 고려하여, 사전에 Gemini API 실서버 E2E 검증을 100% 통과하고 안전하게 보존된 `INSP-001398`(T03 조도 저하 진단 보고서)의 실제 결과를 화면에 로드하여 보여드리겠습니다."*
    - (숏컷 `[T03:Warn]` 클릭하여 실서버 보고서 렌더링 확인)

### [6단계] REINSPECT 이미지에 대한 Gemini Vision 2차 분석 (소요: 30초)

- **발표자 멘트:**
  > "그렇다면 조도가 어두워진 이 병은 실제로 깨진 것일까요? 이를 확인하기 위해 신규 개발된 `Gemini Vision` 시각 분석 패널을 보겠습니다.  
  > 기존 진단 에이전트가 텍스트 로그만 읽었다면, Gemini Vision은 잘라낸 병 원본 PNG 이미지를 직접 멀티모달로 분석합니다.  
  > 현재 화면을 보시면 오프라인 Fake 검증 모드로 동작하고 있으며, 시각적 소견 분류로 `NO_VISIBLE_DEFECT` 또는 `QUALITY_ISSUE`를 반환했습니다.  
  > 저희는 산업 현장의 비인가 외부 이미지 유출과 API 과금을 방지하기 위해 엄격한 안전 게이트를 적용했습니다. 실제 클라우드 LIVE 전송은 관리자 승인 전까지 의도적으로 비활성화(DISABLED)하여 시스템의 안전성을 지키고 있습니다."
- **실행할 UI 동작:**
  1. `Vision Review Panel` 카드 포인팅.
  2. `[FAKE_TEST / OFFLINE MOCK]` 배지 및 비활성화된 `[Run Vision Analysis]` 버튼 확인.
- **기대되는 실제 화면:**
  - 시각적 소견 카드 렌더링, 제2 소견(Second Opinion) 명시, 안전 가드레일 배너 표시.
- **핵심 강조 포인트:**
  - **절대로 "Gemini Vision 실시간 연동 성공"이라고 과장하지 말 것!**
  - "오프라인 데이터 격리 파이프라인 100% 검증 완료, LIVE 어댑터는 보안 게이트로 보호 중"이라고 정직하게 설명.

### [7단계] 작업자 3회 재검사 상한 및 수동 확인 워크플로우 (소요: 30초)

- **발표자 멘트:**
  > "마지막으로 재검사(REINSPECT)가 공정에서 어떻게 종결되는지 보여드리겠습니다.  
  > 만약 작업자가 조명을 조절하지 않고 무한정 재검사를 돌리면 컨베이어가 마비됩니다. VisionInsight는 동일 제품에 대해 **최대 3회까지만 재검사를 허용**합니다.  
  > 3회 연속 REINSPECT가 발생하면 시스템은 자동으로 재검사를 차단하고, 작업자 수동 확인 모달을 띄웁니다.  
  > 작업자는 사유를 입력하고 `HOLD`, `MANUAL_OK`, `MANUAL_NG` 중 하나를 선택하여 공정을 최종 확정합니다. 이 수동 확인 기록 역시 별도의 감사 저장소에 기록되어 원본 모델 검사 이력을 훼손하지 않습니다."
- **실행할 UI 동작:**
  1. 재검사 그룹(`RIG-*`) 정보 및 `Attempt: 1/3` 표시 확인.
  2. (사전 생성된 3회 초과 검사가 있을 경우) 수동 확인 다이얼로그 표시 및 `HOLD` 상태 확인.
- **기대되는 실제 화면:**
  - 재검사 횟수 카운터, 동일 제품 확인 체크박스, 수동 판정 결과 배지 표시.
- **마무리 멘트:**
  > "이처럼 VisionInsight는 단순한 모델 데모가 아니라, 실제 공장에서 발생할 수 있는 조명 저하, 센서 오작동, 작업자 개입에 이르는 전 과정을 완벽히 방어하는 견고한 산업용 AI 시스템입니다. 경청해 주셔서 감사합니다."

## 3. 돌발 상황 발생 시 비상 대응 매뉴얼 (Troubleshooting)

| 돌발 상황 | 원인 | 즉시 취할 조치 (10초 이내 대응) |
| :--- | :--- | :--- |
| **LiveView 비디오가 멈춰 있고 재생되지 않음** | 비디오 소스 디코딩 지연 | 당황하지 말고 우측 숏컷 `[T01:OK]` 클릭하여 즉시 정적 이미지 검사 뷰로 전환 후 설명 진행. |
| **`[Grab]` 클릭 시 401 오류 발생** | Vite 프록시 세션 만료 | 브라우저 F5 새로고침 1회 수행. 그래도 안 되면 저장된 `INSP-001652` 번호를 직접 입력하여 조회. |
