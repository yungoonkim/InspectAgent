### [1:30 ~ 3:00] 2. 전체 시스템 아키텍처 및 이중 저장소 설계

"VisionInsight의 전체 아키텍처는 프론트엔드, 검사 엔진, 판정 및 저장 계층, AI 진단 계층이 느슨하게 결합된 모듈러 구조입니다.

화면단은 React 19와 TypeScript 기반으로 구축되었습니다. 특히 머신비전 검사관을 위해 Canvas 2D 기반의 커스텀 뷰어를 자체 개발하여, 마우스 휠 조작 시 포인터 위치가 고정되는 아핀 변환 수식을 적용해 **100%부터 4000%까지 극초고배율 확대**를 지원합니다. 3200% 이상 확대하면 픽셀 셀 내부에 정수 Gray Value(0~255)가 실시간 표시됩니다.

백엔드는 Python FastAPI 기반의 비동기 마이크로서비스 구조입니다.  
여기서 주목해 주실 부분은 **저장 계층의 분리 설계**입니다.  
비유하자면, 저희는 공정의 데이터를 **'설정 장부'**와 **'블랙박스'**로 나누었습니다.
- **PostgreSQL**은 작업자가 마우스로 드래그하여 등록하는 관심 영역(ROI) 프리셋을 관리합니다. ROI 설정은 언제든 수정될 수 있고 관리자의 버전 승인 워크플로우를 거쳐야 하므로 관계형 DB가 적합합니다.
- 반면, **JSONL 감사 저장소**는 비행기의 블랙박스와 같습니다. 한 번 검사된 결과(`inspections.jsonl`)와 시작부터 끝까지의 타임라인 로그(`inspection_logs.jsonl`)는 어떠한 경우에도 수정되거나 덮어쓰이지 않는 **Append-only** 방식으로 영구 기록됩니다. 여기에 단 1회의 추론에서 추출된 2차원 결함 맵이 `.npz`, `.json`, `_overlay.png`라는 Sidecar 아티팩트로 영구 결합됩니다."

### [3:00 ~ 4:30] 3. 무감독 이상 탐지 원리와 PatchCore 벤치마크

"비전 결함 검출의 핵심 엔진인 **PatchCore**의 원리를 설명하겠습니다.

쉬운 비유를 들자면, PatchCore는 **'정상 병 사진 수천 장이 꽂힌 도감'**을 머릿속에 외우고 있는 검사관입니다.  
공장에서 불량 병 사진을 수집하는 것은 매우 어렵습니다. PatchCore는 정상 병 180장의 패치 임베딩을 ResNet-18 백본으로 추출한 뒤, Coreset 서브샘플링을 통해 메모리 뱅크(`[9216, 384]`, 24MB)에 압축 보관합니다.  
새로운 병이 들어오면, 이미지의 각 패치를 도감 속 정상 패치들과 비교하여 **가장 닮지 않은 최대 거리**를 구합니다. 이 거리가 바로 **이상 점수(Anomaly Score)**입니다.

저희는 독립된 정상 검증셋 29장의 통계를 기반으로 고정 임계값 **`34.1442` ($\mu + 3\sigma$)**를 산출했습니다. 점수가 이 임계값을 넘으면 모델 소견은 NG, 이하면 OK가 됩니다. CPU 단일 코어 환경에서 순수 추론 속도는 평균 **42.53ms**로 실시간성을 만족합니다.

하지만 한계도 명확합니다. 과거 83장 테스트 세트 평가에서 Precision은 100%였으나 Recall은 **50.79%**에 머물렀습니다. 63개 불량 중 32개는 완벽히 잡았지만 31개의 미세 파손이나 투명 오염을 놓쳤습니다. 256×256 패치 축소 과정에서 1~2픽셀의 미세 균열이 정상 배경에 묻히기 때문입니다. 저희는 이 한계를 숨기지 않고 뒤에서 말씀드릴 OpenCV 기하 검사와 Gemini 멀티모달 융합으로 풀어나가고 있습니다."

### [4:30 ~ 6:00] 4. 영상 품질 검사와 6대 우선순위 판정: INSP-001669 실증

"VisionInsight의 가장 독창적인 엔지니어링 성과는 **'모델 소견'과 '서버 최종 판정'의 엄격한 분리**입니다.

이를 이해하기 위해 쉬운 비유를 들겠습니다.  
시험을 치르는 수험생이 문제를 몰라서 틀린 것은 '실력 부족(제품 불량 NG)'입니다.  
하지만 시험 도중 정전이 되어 시험지가 안 보여서 답을 못 썼다면, 그 학생을 탈락시켜야 할까요? 아닙니다. 전등을 켜고 '재시험(REINSPECT)'을 보게 해야 합니다.

저희 서버의 `decision.py`는 6대 우선순위 규칙을 가집니다.
1. 파이프라인 실패 $\rightarrow$ `ERROR`
2. **영상 품질 경고(조도 저하 등) $\rightarrow$ `REINSPECT` (모델 NG보다 무조건 우선!)**
3. 모델 미완료 또는 소견 불능 $\rightarrow$ `REINSPECT`
4. 품질 정상 + 모델 NG $\rightarrow$ `NG`
5. 품질 정상 + 모델 OK $\rightarrow$ `OK`
6. 기타 미정의 상태 $\rightarrow$ `REINSPECT`

이 규칙이 실제로 입증된 증거가 오늘 디스크에 기록된 **`INSP-001669` 검사**입니다.
- **ROI Crop:** 291×278 해상도, SHA256 `ad028428...`
- **이상 점수:** `31.5006` (임계값 34.1442 이하 $\rightarrow$ **모델 소견: OK**)
- **평균 밝기:** `57.41` (정상 기준치 125.0 미달 $\rightarrow$ **품질: WARNING_LOW_BRIGHTNESS**)
- **서버 최종 판정:** **`REINSPECT`**

모델은 정상(OK)이라고 보았지만, 조도가 어두워 신뢰할 수 없으므로 시스템이 최종 판정을 REINSPECT로 강제한 것입니다. 이 검사는 단조 증가 ID로 묶여 6건의 타임라인 로그, Anomaly Map 3종 아티팩트와 100% 정합성을 유지하고 있습니다."

### [6:00 ~ 7:30] 5. Gemini AI 진단 에이전트와 Gemini Vision Judge

"이렇게 REINSPECT로 판정된 병에 대해 두 가지 AI 기술이 유기적으로 결합합니다.

첫째, **Gemini Diagnostic Agent (로그 기반 공정 진단)**입니다.  
LLM에게 비전 검사 판정권을 주면 환각을 일으킵니다. 저희는 에이전트에게 4대 읽기 전용 도구(`get_inspection_result`, `get_execution_logs`, `analyze_image_quality`, `get_inspection_history`)만 제공했습니다.  
에이전트가 작성하는 모든 문장은 시스템 로그와 **JSON Pointer로 1:1 일치하는 Fact Catalog**에 앵커링되어야만 채택됩니다. 에이전트는 '조도가 57.41로 낮아 카메라 조명 점검이 필요하다'는 가설과 권고를 제시하지만, 서버의 최종 판정인 REINSPECT를 번복할 수는 없습니다.

둘째, 신규 아키텍처인 **Gemini Vision Judge (이미지 기반 2차 판정)**입니다.  
텍스트 로그만 읽던 Diagnostic Agent와 달리, REINSPECT된 원본 병 Crop PNG 바이트를 직접 Gemini 멀티모달 모델에 전달하여 시각적 결함 여부를 독립적으로 판정(OK/NG/REINSPECT)합니다.  
클라이언트의 조작된 URL을 거부하고 서버의 SHA256 검증을 통과한 원본 바이트만 전달하며, 결과는 별도의 `vision_reviews/state.json`에 원자적 파일 락으로 영구 보존됩니다.  
이 판정은 서버의 1차 판정을 바꾸지 않고 작업자의 의사결정을 지원하는 독립된 2차 소견(Second Opinion)으로 작동합니다. [최종 확인 필요: LIVE API 연동 게이트 및 응답 표출 상태]"

### [7:30 ~ 8:45] 6. 재검사 3회 정책과 작업자 수동 확인 워크플로우

"산업 현장에서 자동화 시스템이 갖추어야 할 마지막 덕목은 **'공정 마비 방지'**입니다.

조도가 계속 어두운 상태인데 시스템이 무한정 REINSPECT를 반복하면 컨베이어 벨트는 멈춰 서게 됩니다.  
VisionInsight는 동일 제품(`product_id`)에 대해 **최대 3회까지만 재검사를 허용**하는 엄격한 상한선(Cap)을 둡니다.

3회 연속 REINSPECT가 발생하면, 시스템은 4번째 검사 요청을 `409 Conflict`로 자동 차단하고, 작업자 화면에 **수동 확인 모달**을 팝업합니다.  
작업자는 사유와 작업자 표시명을 입력한 뒤, `HOLD`, `MANUAL_OK`, `MANUAL_NG` 중 하나를 선택해 공정을 확정합니다. 이 수동 확인 기록 역시 별도의 감사 저장소에 보존되며, 과거 3회의 원본 모델 검사 결과는 계속 REINSPECT로 보존됩니다. 자동화 알고리즘의 판단과 인간 작업자의 책임을 명확히 분리한 것입니다."

정직한 데이터, 결정론적 안전 규칙, 그리고 설명 가능한 생성형 AI의 결합. 이것이 바로 VisionInsight가 제시하는 차세대 스마트 팩토리의 비전입니다. 감사합니다."

# [산출물 4] 예상 질문 15개 및 모범 답변 (Q&A Master Sheet)

---

### Q1. 프론트엔드와 백엔드를 굳이 별도 포트로 분리하여 개발한 이유와 발생한 문제는?
- **답변:**  
  "산업 현장의 HMI 대시보드(React)와 영상 처리/추론 엔진(FastAPI)의 관심사를 분리하고 확장성을 확보하기 위해 분리했습니다.  
  이 과정에서 `localhost:5173`과 `127.0.0.1:8000` 간 크로미움의 `SameSite=Strict` 쿠키 차단으로 인한 Grab 401 오류가 발생했습니다. 저희는 백엔드의 엄격한 보안을 허물지 않고, Vite 프록시(`/api`)를 도입해 브라우저 관점의 단일 출처(Same-Origin) 구조를 완성하여 정석으로 해결했습니다."

---

### Q2. PostgreSQL과 JSONL이라는 두 가지 저장소를 혼합하여 사용하는 이유는?
- **답변:**  
  "데이터의 **수정 가능성(Mutability)**에 따른 최적화입니다.  
  작업자가 마우스로 지정하는 ROI 설정은 수시로 수정되고 관리자 버전 승인을 거쳐야 하므로 관계형 모델과 트랜잭션이 지원되는 **PostgreSQL**이 적합합니다.  
  반면, 검사 결과와 생명주기 이벤트 로그는 사후 감사 시 단 1바이트도 위변조되어서는 안 되는 공정 블랙박스입니다. 따라서 쓰기 속도가 빠르고 수정이 불가능한 **Append-only JSONL**을 사용하여 완벽한 감사 추적성을 확보했습니다."

---

### Q3. 비지도 이상 탐지 모델 중 PatchCore를 선택한 기술적 이유는?
- **답변:**  
  "공정 환경에서는 불량 데이터의 수집과 라벨링이 극히 어렵기 때문에 정상 이미지만으로 학습하는 무감독(Unsupervised) 학습이 필수적입니다.  
  Autoencoder나 GAN 계열은 재구성 오차로 인해 결함 경계가 흐려지는 문제가 있지만, PatchCore는 사전 학습된 ResNet 임베딩의 Coreset 메모리 뱅크를 활용하여 **CPU 단일 코어에서도 평균 42ms라는 초저지연 추론**이 가능하며, 이상 점수뿐만 아니라 **2차원 결함 위치(Anomaly Map)를 단 1회 추론에서 정확히 추출**할 수 있어 채택했습니다."

---

### Q4. 모델 소견은 OK인데 서버 최종 판정이 REINSPECT로 바뀐 이유는? (INSP-001669)
- **답변:**  
  "머신비전 시스템의 안전 가드레일 정책 때문입니다.

### Q5. REINSPECT는 왜 필요하며, 왜 3회로 횟수를 제한했습니까?
- **답변:**  
  "조도 저하나 흔들림 등 일시적 촬영 불량으로 멀쩡한 제품을 불량(NG) 폐기하는 과잉 판정을 막기 위해 재검사 상태가 반드시 필요합니다.  
  하지만 조명이 계속 고장 난 상태에서 무한정 재검사를 허용하면 컨베이어 벨트가 마비됩니다. 따라서 VisionInsight는 동일 제품에 대해 **최대 3회까지만 재검사를 허용**하고, 3회 연속 REINSPECT 시 자동으로 검사를 잠그고 작업자가 직접 개입하는 수동 확인(HOLD/MANUAL)으로 전환하도록 설계했습니다."

### Q6. Gemini Diagnostic Agent와 Gemini Vision Judge의 근본적인 차이는?
- **답변:**  
  "분석하는 데이터와 동작 메커니즘이 완전히 다릅니다.  
  - **Diagnostic Agent:** 검사 수치, 조도 통계, 이벤트 타임라인 로그라는 **텍스트/JSON 데이터**를 Function Calling 도구 4개로 조회하여 공정 원인을 분석하는 '진단 보고서 작성기'입니다.  
  - **Vision Judge:** 잘라낸 병 원본 Crop **PNG 바이너리 이미지 자체**를 멀티모달 모델에 전달하여 시각적 결함 여부를 직접 판독하는 '독립 2차 시각 판정기'입니다.  
  두 엔진 모두 서버의 1차 판정을 임의로 바꾸지 못하도록 안전 가드레일이 적용되어 있습니다."
