## 1. 목적과 범위

VisionInsight는 기존 **MVTec Bottle 이미지로 Codex가 합성한 8초짜리 컨베이어 동영상**을 활용하여, 산업용 비전 검사 프로그램과 유사한 사용 경험을 제공하는 **포트폴리오/시연용 웹 애플리케이션**이다.

- 실제 카메라·컨베이어·PLC와 물리적으로 연동되는 시스템은 **이번 범위가 아니다**.
- 동영상 재생/일시 정지를 컨베이어 이동/정지로 **시뮬레이션**한다.
- 실제 동작하는 Python FastAPI + PatchCore 검사 백엔드를 재사용하며, 필요 시 Gemini Agent가 **확정된 검사 근거**를 설명한다.
- 최우선 UX는 **저장된 ROI 기반 자동 검사**, 보조 UX는 **ImageView 기반 수동 검사**이다.
- 자동·수동은 이미지 획득 및 검사 시작 방식만 다르고, **같은 검사 엔진·판정 정책·저장 구조**를 사용한다.

### 확정된 사용 시나리오

**AUTO:** `LiveView 컨베이어 재생 → 제품 검사 위치 도착 → 자동 정지 → 자동 Grab → 저장된 ROI 적용 → PatchCore 검사·결과 확정 → 검사 완료 후 자동 재생 → 다음 제품`

**MANUAL(파일):** `저장된 이미지 불러오기 → ImageView → 확대/픽셀 값 확인 → 사용자 ROI 지정 → 검사 버튼 → 동일한 PatchCore 검사·결과 확인`

**MANUAL(Live에서 획득):** `LiveView 일시 정지 → Grab 버튼 → 서버 추출 PNG를 ImageView에 표시 → ROI 지정 → 검사 버튼 → 결과 확인 → LiveView 재생 버튼으로 복귀`

> **구분:** AUTO에서는 사용자가 Grab/검사 버튼을 누르지 않는다. MANUAL에서는 사용자가 ROI를 정하고 검사 버튼을 누른다. **AUTO 역시 매번 ROI를 그리는 것이 아니라 이전에 저장한 ROI를 사용한다.**

## 4. 공통 시스템 구성

```text
[React LiveView] -- video_id/frame_index --> [FastAPI VideoFileSource]
      |                                             |
      |                                     원본 프레임 PNG
      |                                             v
      +---- Grab 결과(capture_id) ----------> [CaptureStore]
                                                    |
[React ImageView] <--- 캡처/저장 이미지 ------------+
      |                                             |
      +-- ROI 좌표 또는 저장 ROI 설정 --------------> [ROI 유효성 검사/추출 어댑터]
                                                    |
                                                    v
                                         [기존 ImageRegistry 연결]
                                                    |
                                                    v
                                        [기존 PatchCore 검사 워크플로]
                                                    |
                                                    v
                                    [Inspection 결과/이력/로그 저장]
                                                    |
                                                    v
                                   [React 결과 표시]  [Gemini Agent 선택 분석]
```

**설계 원칙**

1. AUTO와 MANUAL은 동일한 검사 실행 경로로 수렴한다. 수동만 다른 모델·임계값을 사용하지 않는다.
2. AI 판정(`OK/NG/UNKNOWN`)과 서버 최종 판정(`OK/NG/REINSPECT/ERROR`)의 기존 정책을 그대로 보존한다. Agent는 서버 결과를 변경하지 않는다.
3. **Grab은 이미지 획득**, **ROI는 검사할 부분 선택**, **Inspection은 모델 추론**으로 책임을 분리한다.
4. `product_id`, `video_id`, `capture_id`, `image_id`, `inspection_id`, `roi_id`는 각각 다른 식별자다. 서로 바꿔 쓰지 않는다.
5. 캡처 또는 ROI가 부적절하면 검사 **시작 전**에 거절/재선택을 유도한다. 이를 제품 자체의 `NG`로 오인하지 않는다.

## 5. AUTO: 저장된 ROI 기반 자동 검사

### 5.1 시작 조건

AUTO 실행 전에 다음을 확인한다.

- 승인된 H.264 영상이 정상 등록됨 (`video_id`, `source_revision`).
- AUTO 검사에 사용할 `product_id`와 **저장된 ROI**가 선택·검증됨.
- 저장된 ROI가 적용될 **원본 이미지 해상도**와 영상 해상도가 일치하거나, 명시적으로 검증된 변환 규칙이 있음.
- ROI의 위치·크기가 제품을 온전히 포함하고, PatchCore의 기존 입력 조건과 맞는지 확인됨.
- 제품별 자동 검사 트리거 프레임이 **실제 영상 내용으로 확인**됨. 데이터셋 정답이나 불량 라벨을 트리거 결정에 사용하지 않음.

> ROI 설정만 저장했다고 제품 도착을 자동 감지하는 것은 아니다. MVP에서는 실제 영상에서 병이 검사 위치에 온전히 보이는 프레임을 미리 검증하여 트리거를 등록한다. 향후 객체 위치 감지는 별도 기능이다.

### 5.2 자동 검사 상태 흐름

```text
READY → RUNNING → STOPPING_AT_INSPECTION_POSITION
      → GRABBING → VALIDATING_CAPTURE_AND_ROI
      → INSPECTING → RESULT_COMMITTED → RESUMING → RUNNING

                     └─ 실패/부적합 → ERROR_HOLD(정지 유지·재시도/수동 확인)
```

1. LiveView가 승인된 합성 영상을 재생한다. 화면에는 `Simulation Live` 또는 `Demo Live`임을 표기한다.
2. 사전에 검증된 제품별 목표 `frame_index`에 도착하면 자동으로 영상 재생을 멈추고 **해당 정확한 프레임으로 위치를 정렬**한다.
3. React는 `video_id + source_revision + frame_index`로 서버 Grab을 요청한다.
4. FastAPI가 원본 H.264 파일에서 **요청 프레임**을 추출해 PNG를 저장하고 `capture_id`와 실제 추출 인덱스를 응답한다.
5. 백엔드가 해당 캡처에 **저장된 ROI의 원본 픽셀 좌표**를 적용하고, 경계·크기·유효성 검증을 거쳐 검사 입력을 준비한다.
6. 기존 PatchCore 및 서버 판정 로직으로 검사하고 `inspection_id`/결과/로그를 저장한다.
7. **검사 결과가 서버에 확정 저장된 뒤** LiveView 영상 재생을 재개한다. 다음 트리거 전에는 중복 검사를 하지 않는다.
8. 검사 실패, 저장 실패, 부적절한 ROI, 타임아웃 등이 생기면 `ERROR_HOLD`에서 정지하고 오류/재시도/재개 선택을 표시한다.

**0.5초 정지:** 실제 사용자 요구의 필수 검사시간으로 고정하지 않는다. 필요하면 데모 연출용 **최소 정지시간** `max(0.5초, 실제 검사 완료까지 걸린 시간)`을 선택적으로 적용한다. 서버 전체 지연 시간은 따로 측정해야 한다.

**Agent:** 검사 확정 후 필요한 경우 비동기로 분석한다. Gemini의 수십 초 응답을 영상 재개 필수 조건으로 삼지 않는다.

### 5.3 반복 재생과 중복 검사 방지

8초짜리 영상의 loop가 시작되면 **재생 사이클 ID**를 새로 부여한다. 각 제품/트리거 인덱스는 해당 사이클에서 최대 한 번 자동 실행되도록 한다. 동일 검사 요청의 재시도나 중복 이벤트에는 요청 ID 또는 중복 방지 키를 사용한다.

`timeupdate` 이벤트만 사용하면 정확한 프레임 정지를 보장할 수 없다. React의 `requestVideoFrameCallback` 등 지원 기능과 pause/seek 재정렬을 검토하되, 최종 검사 이미지는 언제나 **서버 Grab 결과 PNG**를 진실 원본으로 사용한다. 프레임 완전 동기화는 별도 통합 검증 대상이다.

## 6. MANUAL: ImageView 기반 수동 검사

### 6.1 저장 이미지 불러오기

1. 사용자가 **서버에 등록된/허용된 이미지**를 선택한다. 외부 경로·임의 파일명을 서버 경로에 그대로 전달하지 않는다.
2. ImageView에 해당 이미지가 표시된다.
3. 확대/이동하며 제품 외관을 확인하고 마우스로 ROI를 지정·이동·조절한다.
4. 원본 픽셀 좌표 `x, y, width, height`와 해상도, 선택 범위를 확인한다.
5. 사용자가 **검사** 버튼을 누르면 동일한 백엔드 ROI 검사 워크플로로 진행한다.
6. 결과와 로그를 표시한다. ROI를 **AUTO 기본 ROI로 저장**하는 것은 별도 버튼 및 확인 과정으로 수행한다. 임의의 수동 검사 ROI가 자동 설정을 덮어쓰지 않는다.

### 6.2 LiveView에서 Pause → Grab → 수동 검사

1. 사용자가 LiveView의 **Pause**를 누르면 데모 컨베이어 영상이 멈춘다.
2. 정지한 프레임이 병을 반쯤만 보여주면 이전/다음 프레임 이동 또는 재생 후 다시 Pause하여 적절한 장면을 선택한다.
3. 사용자가 **Grab**을 누르면 FastAPI가 선택 프레임을 PNG로 캡처하고 `capture_id`를 반환한다.
4. 반환된 **서버 PNG를 ImageView에 표시**한다. 화면에 보이던 동영상 프레임과 동일하다고 무조건 가정하지 않는다.
5. ImageView에서 사용자가 ROI를 정하고 검사 버튼을 누른다.
6. 검사가 끝나도 수동 모드에서는 자동으로 LiveView를 재생하지 않는다. 사용자가 **LiveView**로 돌아가 **Play**를 눌러 재개한다.

수동 Pause는 자동 검사 위치 도착 신호가 아니므로, **Pause만으로 자동 PatchCore 검사를 시작하지 않는다**. AUTO는 사용자가 명시적으로 AUTO 모드를 시작했을 때만 구동한다.

### 6.3 부적절한 캡처 처리

- 병이 프레임 밖에서 잘림, 저장 ROI에서 이탈, ROI에 병이 충분히 포함되지 않음 등이 발견되면 **재Grab 또는 ROI 재설정**을 안내한다.
- 모델 검사를 실행하지 않은 이미지에 대해 제품 `NG` 결과를 생성하지 않는다.
- 초기에 완전 자동 병 검출 모델이 없으므로 **사람의 확인 및 검증된 트리거 목록**을 활용한다.
- 이미지 경계 안에 ROI가 있다는 사실만으로 병 전체가 보인다고 증명되지는 않는다.

## 7. ImageView — 이미지 검사 도구 요구사항

### 7.1 표시 및 조작

- 이미지 로드, Zoom In/Out, 마우스 휠 확대/축소, Pan, Fit, 100%(1:1) 보기.
- 확대 시 필요하면 픽셀 격자(Nearest-neighbor 표현 또는 격자 오버레이)를 표시.
- 사각형 ROI 생성, 이동, 크기 조절, 삭제/초기화, 좌표 및 크기 표시.
- 스크린/CSS 좌표와 원본 이미지 픽셀 좌표를 정확히 변환. **검사와 ROI 저장에는 원본 좌표만 사용**.
- ROI가 이미지 경계를 벗어나거나 최소 크기를 충족하지 못하면 검사 버튼 비활성화/오류 표시.
- ROI 저장/불러오기: `roi_id`, ROI 설정 버전, 기준 영상·해상도·대상 `product_id`와의 호환성을 관리.

### 7.2 픽셀 Inspector / GV

**8-bit Grayscale:** 픽셀 하나의 Gray Value(`GV`)는 **0~255**.

**8-bit RGB Color:** 픽셀 하나의 채널값은 **R(0~255), G(0~255), B(0~255)**.

예를 들어 원본 이미지가 **500×500이면 총 250,000개 픽셀**이 있으며, RGB 이미지라면 픽셀당 세 채널이 존재한다. 모든 숫자를 한 화면에 동시에 쓰는 것이 아니라, **마우스가 가리킨 원본 픽셀의 좌표와 값을 확인**한다.

```text
Pixel Inspector (설명용 예시 — 실제 측정값 아님)
좌표  X=241, Y=137
RGB   R=128, G=142, B=156
Gray  GV=140  [RGB에서 계산한 경우 '계산값'으로 별도 표시]
이미지  Width=500, Height=500
```

- 화면 확대/축소로 색이 보간되더라도 **원본 이미지 원시 픽셀 값**을 표시한다.
- Python OpenCV 디코딩의 **BGR**과 브라우저 표시의 **RGB** 순서를 혼동하지 않는다.
- 원본이 그레이스케일이면 GV 자체를 표시하고, RGB 원본에서 그레이 값을 변환해 표시한다면 **변환된 값**임을 구분한다.
- 원본 채널 수·비트 깊이가 8-bit RGB/Gray가 아닌 경우에는 단순 0~255라고 주장하지 않고 실제 자료형을 확인한다.
- 픽셀 조회용 고해상도 파일의 처리 성능·메모리 사용량은 Day6 UI 구현 시 검증한다.

## 8. 저장된 ROI의 데이터 계약

### 8.1 권장 ROI 설정 정보(설계 예시, 미구현)

```json
{
  "roi_id": "ROI-000001",
  "roi_version": 1,
  "product_id": "<기존 제품 식별자>",
  "source_video_id": "VID-000001",
  "reference_width": 1920,
  "reference_height": 480,
  "coordinate_system": "ORIGINAL_IMAGE_PIXELS_TOP_LEFT",
  "shape": "rectangle",
  "x": 0,
  "y": 0,
  "width": 1,
  "height": 1,
  "enabled_for_auto": false
}
```

> 위 좌표는 **스키마 형태만 보여주는 임시 값**이며 실제 ROI로 사용하면 안 된다. 병이 온전히 들어오는 프레임과 해당 제품의 실제 위치를 확인한 뒤 ROI 좌표를 확정한다.

### 8.2 자동 검사 적용 규칙

- AUTO는 활성화된 **저장 ROI 버전**을 읽으며, 실행 중 ROI를 임의로 변경하지 않는다.
- ROI는 캡처 원본 좌표를 기준으로 검증한다. UI 확대 비율을 서버 ROI 크기로 사용하지 않는다.
- ROI가 해당 프레임의 병 전체를 포함하는지 **실제 영상으로 검증**해야 한다.
- ROI에서 추출한 이미지를 기존 `image_id` 기반 워크플로에 넣으려면 **별도 등록/어댑터**가 필요하다. `capture_id`를 `image_id`로 직접 치환하지 않는다.
- 기존 PatchCore의 입력 형태 및 전처리·임계값이 고정되어 있으므로, 임의 리사이즈·회전·크롭이 검사 의미를 바꾸지 않는지 검증한다.
- ROI 설정을 자동 검사용으로 저장할 때 사용자가 적용 대상으로 선택한 영상/제품에 한정한다.

## 9. FastAPI 연동 API (Day5 Step 2 Phase B 이후 구현 예정)

| API | 역할 | 현재 상태 |
|---|---|---|
| `GET /videos` | 승인 영상 목록 | **신규 설계** |
| `GET /videos/{video_id}` | FPS/해상도/프레임 수/revision 메타데이터 | **신규 설계** |
| `GET/HEAD /videos/{video_id}/stream` | 브라우저 동영상 스트리밍, Range/206·416 | **신규 설계** |
| `POST /videos/{video_id}/grab` | `frame_index + source_revision`로 프레임 추출/PNG 생성 | **신규 설계** |
| `GET /captures/{capture_id}` | 캡처 메타데이터 | **신규 설계** |
| `GET /captures/{capture_id}/image` | 저장된 PNG 조회 | **신규 설계** |
| ROI 설정 저장/조회·ROI 검사 API | 자동 ROI 및 ImageView 검사 연결 | **Step 3에서 계약 확정** |
| 결과/로그/이력 조회 API | React 결과 화면 및 조사 | **Step 4에서 계약 확정** |
| 기존 `POST /inspections` | `product_id + image_id` 기반 기존 검사 시작 | **기존 구현** |
| 기존 `POST /analyze/{inspection_id}` | 검사 결과에 대한 Agent 분석 | **기존 구현** |

**권장 Grab 요청/응답 원칙**

- 프레임 식별은 `video_id + frame_index(0~239) + source_revision`로 한다. 서버는 인덱스 범위를 엄격히 확인한다.
- 서버 Grab은 요청마다 독립 디코더를 사용하고, 최초에는 **순차 디코딩을 정확성 기준**으로 삼는다.
- 서버가 실제 추출한 `frame_index`와 PNG가 최종 기준이다. 브라우저 시각에서 계산한 값은 요청값이다.
- 캡처 ID는 서버 발급 불투명 식별자; 캡처 이미지와 메타데이터에 소유 세션 검증·TTL 적용.
- 캡처 단계 자체는 **검사 시작이 아니므로 `inspection_id`를 발급하지 않는다**.
- 임의 파일 경로/URL/클래스 라벨/외부 Ground Truth가 API로 유입되지 않도록 한다.

### AUTO 실행 시 권장 서버 처리 경계

`Video Grab → CaptureStore → 저장 ROI 검증/ROI 파일 생성 → 기존 ImageRegistry 등록 → 기존 Inspection 실행 → 서버 결과 확정/저장`

자동 동작의 상태제어는 우선 React 데모 컨트롤러가 담당하되, 서버가 ROI/캡처/검사 권한·유효성을 재검증해야 한다. 상태 표시만 바꾼다고 실제 검사를 했다고 표현하지 않는다.

## 10. LiveView UI / Toolbox 동작

### 10.1 화면 구성

- 영상 영역: 1920×480 비율을 가능한 한 유지한 `Simulation Live`.
- 상단/옆 상태: `AUTO / MANUAL`, `RUNNING / PAUSED / GRABBING / INSPECTING / COMPLETED / ERROR_HOLD`.
- 하단 툴박스: **Auto Start/Stop(모드 선택), Play(▶), Pause(Ⅱ), Grab(카메라 아이콘), ImageView(이미지 아이콘)**.
- 최근 결과: `inspection_id`, 판정, 검사 완료 여부, 오류 메시지.
- 표시해야 할 검사 대상: 선택한 `product_id`, `roi_id`/버전, `video_id`, 현재 프레임/시간.

### 10.2 버튼별 의미

| 버튼 | AUTO 모드 | MANUAL 모드 |
|---|---|---|
| AUTO Start | 등록 트리거 감시 및 자동 검사 실행 | AUTO 모드로 명시적 전환 시 실행 |
| Pause `Ⅱ` | 사용자 개입 시 안전한 일시정지/모드 전환 처리 | 동영상 일시정지, 검사 **자동 시작 아님** |
| Play `▶` | 자동 검사 진행 중에는 무단 재개 금지; 완료/사용자 확인 후 재개 | 사용자 누르면 동영상 재생 |
| Grab | AUTO에서는 자동 호출, 수동 버튼은 비활성화하거나 운영자 개입 모드로 구분 | 정지한 프레임을 FastAPI에서 PNG 캡처 |
| ImageView | 최근 검사 이미지/캡처 조회 | 불러온 이미지 또는 수동 Grab PNG에서 ROI/픽셀 조회/검사 |

버튼 활성화는 실제 상태와 일치해야 한다. 검사 중 이중 Grab·중복 검사·AUTO/MANUAL 전환 경쟁 조건을 막는다.

## 11. 오류·품질·안전 정책

| 상황 | 권장 동작 |
|---|---|
| 병이 프레임 경계에서 반만 보임 | 검사 전에 재프레임 선택/다음 적합 트리거 선택. **제품 NG 아님** |
| 저장된 ROI 없음/해상도 불일치/범위 이탈 | AUTO 시작 거부 또는 `ERROR_HOLD`, ROI 설정 안내 |

| 영상 변경(revision 불일치) | Grab 거절 및 영상 메타데이터 갱신 요청 |

| PatchCore `NG` | 검사 자체가 **정상 완료된 결과**로 처리. `NG`만으로 기술 오류로 간주하지 않음 |
| Gemini 응답 지연/실패 | 검사 완료·컨베이어 재개에 영향을 주지 않으며, Agent 분석 상태만 별도 표시 |
| 끝 프레임·loop | 다음 사이클로 전환하며 제품별 자동 검사 중복 방지 상태 초기화 |

보안: 영상 등록 ID에만 파일 연결, 경로 탐색 차단, 캡처 소유권/TTL, CORS 허용 origin 설정, 운영 로그에 불필요한 제품 식별자 삽입 금지, Ground Truth 완전 격리. 권장 정책은 **구현·검증 전까지 적용 완료로 간주하지 않는다.**

## 13. 수용 테스트(Definition of Done)

**AUTO 시나리오**

- [ ] 저장 ROI 없이 AUTO가 시작되지 않는다.
- [ ] 트리거 프레임에서 영상이 정지하고 서버가 동일 `frame_index`를 캡처한다.
- [ ] 저장 ROI 버전을 적용하고 기존 검사 워크플로를 정확히 한 번 실행한다.
- [ ] 확정 결과/이력을 저장한 뒤 다음 제품으로 영상 재생을 재개한다.
- [ ] NG는 제품 판정으로 표시하며, 검사 실패는 ERROR_HOLD로 구분한다.
- [ ] 8초 loop 및 재시도에서 중복 검사가 발생하지 않는다.

**MANUAL 시나리오**

- [ ] 서버 허용 이미지 불러오기와 Pause → Grab → ImageView 이동이 동작한다.
- [ ] 잘린 병은 프레임 조정·재Grab이 가능하며 사용자 확인 전 검사하지 않는다.
- [ ] ROI를 그리고/수정하고 검사 버튼을 누르면 AUTO와 **동일한 PatchCore/threshold/서버 판정**을 사용한다.
- [ ] 수동 ROI는 별도의 명시적인 저장 없이는 AUTO 저장 ROI를 변경하지 않는다.
- [ ] MANUAL 검사 후 Play 버튼으로 LiveView에 돌아갈 수 있다.

**ImageView 시나리오**

- [ ] 줌/팬/100%/Fit 및 원본 좌표 기반 ROI 변환이 정상 작동한다.
- [ ] 8-bit Gray 원본은 0~255 GV, 8-bit RGB 원본은 R/G/B 각각 0~255를 정확히 표시한다.
- [ ] 확대 보간 결과가 아닌 **원본 픽셀** 값을 표시한다.
- [ ] ROI 경계/크기/해상도 검증이 서버에서도 동작한다.

**통합·보호**

- [ ] Agent 호출 없이도 검사 완료 및 AUTO 재생이 가능하다.
- [ ] 기존 Agent 조회 도구/판정 정책/임계값이 유지된다.
- [ ] 영상·데이터셋 원본과 보호 JSONL 및 Ground Truth가 보존된다.
- [ ] 결과 보고에 **합성 시뮬레이션 영상**과 실제 공장/PLC/카메라 미연동을 명시한다.
