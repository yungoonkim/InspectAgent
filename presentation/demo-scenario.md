# VisionInsight — 데모 시연 시나리오 및 매뉴얼 (`presentation/demo-scenario.md`) [v5 기술적 정확성 최종 개정판]

> **문서 목적:** 2026년 10월 20일 기술 발표 시, 실서버 E2E 검증을 통과한 T01 양품 및 T03 조도 경고 시나리오의 정적 데모 패키지(`presentation/demo/`)를 활용하여 안전하고 전문적인 시연을 진행하기 위한 매뉴얼입니다.  
> **핵심 원칙:**  
> 1. 시연 중 실제 Gemini 유료 API를 호출하지 않습니다 (발표 현장 네트워크 지연 및 과금 방지).  
> 2. 실제 실서버 E2E 검증 데이터를 100% 동일하게 재생하는 독립 실행형 정적 HTML 데모(`t01-report-demo.html`, `t03-report-demo.html`)를 사용합니다.  
> 3. T01과 T03을 대비하여 "모델 판정은 둘 다 OK지만, 서버 규칙에 의해 최종 판정이 OK와 REINSPECT로 갈라지는 구조"를 시각적으로 보여줍니다.  
> 4. Gemini가 판정을 직접 바꾸거나 실제 물리적인 공장 배출기/컨베이어를 제어하는 것처럼 과장하지 않습니다.

## 1. 데모 환경 및 사전 준비

발표 전 웹 브라우저에 다음 2개 독립 HTML 탭을 미리 열어둡니다:
- **Tab 1: T01 정상 검사 데모** (`presentation/demo/t01-report-demo.html`)
- **Tab 2: T03 조도 경고 데모** (`presentation/demo/t03-report-demo.html`)

*(보조 확인용: 로컬 FastAPI가 기동되어 있다면 `http://localhost:8000/docs`도 열어둘 수 있으나, 본 발표 시연은 검증된 정적 데모 2종을 중심으로 진행합니다.)*

---

## 2. 1분 30초 데모 진행 시나리오 (T01 vs T03 대비 시연)

---

### Step 1: T01 정상 검사 데모 시연 (Tab 1) [30초]

- **수행 작업:**
  - Tab 1 (`t01-report-demo.html`) 화면을 프로젝터에 띄웁니다.
  - 상단 칩 네비게이션에서 `[1. PatchCore 검사]`, `[2. 판정 규칙]`을 순서대로 클릭합니다.
- **화면 관측:**
  - 평균 밝기 135.86, 영상 품질 `NORMAL` (좌측 상단 모식도)
  - 이상 점수 31.3346 < 고정 임계값 34.1442 ➔ 모델 판정: `OK (양품)`
  - 서버 규칙 엔진: `Rule 5` 적용 ➔ 최종 판정: `OK (ALL_CHECKS_PASSED)` (초록색 배지)
- **발표자 멘트:**
  > "먼저 실제 실서버 검증을 마친 T01 정상 검사 데모입니다.  
  > 900×900 해상도에서 평균 밝기 135.86으로 영상 품질이 정상이며, PatchCore 모델의 이상 점수는 31.33으로 임계값 34.14 이하이므로 모델 소견은 OK입니다.  
  > 서버의 비즈니스 규칙 역시 Rule 5를 적용하여 최종 판정을 OK로 확정했습니다."

---

### Step 2: T01 Gemini 진단 및 Evidence 검증 확인 [15초]

- **수행 작업:**
  - 권장 조치 카드의 **`근거 참조: ["F0003"] ➔`** 버튼을 클릭합니다.
- **화면 관측:**
  - 하단 관측 사실 테이블의 `F0003 (/data/final_result = "OK")` 행이 자동으로 하이라이트됩니다.
- **발표자 멘트:**
  > "우측의 Gemini AI 진단 보고서를 보시면, 모델이 '기록된 모델 판정과 종합 판정은 OK이다'라고 정확히 설명합니다.  
  > 권장 조치의 근거 참조를 누르면 서버가 발급한 영수증 `E0001`의 `F0003` 팩트와 1:1로 매핑되어 서버 검증을 통과했음을 직관적으로 확인할 수 있습니다."

---

### Step 3: T03 조도 저하 검사 데모 시연 (Tab 2 전환) [30초]

- **수행 작업:**
  - Tab 2 (`t03-report-demo.html`)로 탭을 전환합니다.
  - 상단 칩 네비게이션에서 `[2. 판정 규칙 (Rule 2 ➔ REINSPECT)]`를 클릭합니다.
- **화면 관측:**
  - 평균 밝기 81.24 저하 감지 ➔ 영상 품질: `WARNING_LOW_BRIGHTNESS` (좌측 상단 주황색 경고)
  - 이상 점수 31.7779 < 임계값 34.1442 ➔ 모델 판정: `OK` (양품 산출)
  - 서버 규칙 엔진: `Rule 2` 적용 ➔ 최종 판정: **`REINSPECT (IMAGE_QUALITY_WARNING)`** (주황색 앰버 배지)
- **발표자 멘트:**
  > "이제 대비되는 T03 조도 저하 데모를 보시겠습니다.  
  > 조명이 어두워져 평균 밝기가 81.24로 떨어졌습니다.  
  > 주목할 점은 PatchCore 모델의 이상 점수는 31.78로 여전히 임계값 미만, 즉 모델 자체는 OK를 산출했다는 것입니다.  
  > 하지만 비정상 조도 환경에서는 모델의 정상 판정을 신뢰할 수 없으므로, 서버 규칙 엔진이 즉시 Rule 2를 발동하여 최종 판정을 제품 NG와 구분하여 **'REINSPECT(재검사 필요)'**로 안전하게 분류했습니다. 이는 서버 판정 상태 분류이며 실제 물리적 폐기나 배출 제어를 수행한 것은 아닙니다."

---

### Step 4: T03 Gemini 도구 2개 조사 및 판정 불변 원칙 강조 [15초]

- **수행 작업:**
  - `[4. Evidence 검증]` 칩 클릭 후, 권장 조치의 **`근거 참조: ["F0004", "F0007"]`** 및 **`["F0003"]`** 버튼을 클릭합니다.
- **화면 관측:**
  - 도구 1(`get_inspection_result`: `E0001`)과 도구 2(`analyze_image_quality`: `E0002`) 영수증 확인
  - 12개 관측 사실(`F0001`~`F0012`) 100% 검증 일치
  - 하단 계측 지표 바: 전체 24.600초 (최종 JSON 18.967초), 9,873토큰, 3단계 HTTP 200 통신 실측치 확인
- **발표자 멘트:**
  > "Gemini는 도구 2개를 순차 호출하여 12개의 팩트를 확인했습니다.  
  > 보시다시피 Gemini는 서버가 확정한 REINSPECT 판정을 단 1글자도 번복하지 않으며, 작업자에게 조명과 카메라 노출을 점검하고 정상 조건에서 수동 재검사할 것을 권고합니다.  
  > 이것이 VisionInsight가 지향하는 '판정은 서버 규칙이, 진단은 AI가' 책임지는 근거 기반 설계입니다."

   - `presentation/demo/t03-report-demo-full.png` (1600×1800)
   - 이미지 뷰어를 띄워 슬라이드와 동일한 2컬럼 레이아웃, Evidence 테이블, Trace 지표 바를 직접 설명합니다.
2. **2차 백업: PDF 벡터 문서 활용**
   - `presentation/demo/t01-report-demo.pdf`
   - `presentation/demo/t03-report-demo.pdf`
   - 표준 PDF 뷰어로 스크롤하며 고대비 UI를 시연합니다.
3. **절대 금지 사항:**
   - ❌ 발표 중 터미널에서 실제 Gemini API를 실시간 호출하지 마십시오.
