## 🎙️ 실전 발표 대본 (구어체)

### 1. 인트로 및 검사 개요 (0:00 ~ 0:20)
> "화면에 보시는 것은 실제 개발 환경에서 검증을 마친 **T01 정상 검사(`INSP-001396`)의 실서버 데이터 기반 인터랙티브 데모 화면**입니다.  
> 상단 고지문처럼, 본 데모는 네트워크 장애나 과금 위험을 원천 차단하기 위해 **실제 서버에 기록된 데이터를 기반으로 재생하는 안전한 정적 데모**입니다.  
> 
> 좌측 상단의 병 와이어프레임은 실제 검사 이미지가 아닌 이해를 돕기 위한 **규격·조도 참고용 개념도**이며, 900×900 해상도에서 평균 밝기 135.86으로 영상 품질이 `NORMAL` 판정을 받았음을 확인할 수 있습니다."

---

### 2. PatchCore 임계값과 모델 판정 (0:20 ~ 0:40)
*(상단 네비게이션에서 **[1. PatchCore 검사]** 칩을 클릭합니다)*

> "화면 중앙의 게이지를 주목해 주십시오.  
> 게이지의 0에서 50은 시각화를 위한 **표시 눈금**이며, 모델의 전체 이론적 범위나 결함 확률을 뜻하지 않습니다.  
> 모델이 산출한 이상 점수(Anomaly Score)는 **31.3346**으로, 고정 임계값 **34.1442**보다 낮아 **PatchCore 모델은 OK로 판정**했습니다.  
> 
> 다만, VisionInsight의 PatchCore는 테스트셋 기준 재현율이 약 50.79%로 미세 결함 미탐 한계가 존재하기 때문에, **이 판정 자체가 제품의 실제 무결점을 보증하지는 않는다**는 점을 시스템 전반에서 명확히 고지하고 있습니다. 단일 CPU 추론 시간은 **41.34ms**가 소요되었습니다."

---

### 3. 서버 규칙 기반 최종 판정 (0:40 ~ 0:55)
*(상단 네비게이션에서 **[2. 판정 규칙]** 칩을 클릭합니다)*

> "바로 아래의 판정 계층입니다.  
> FastAPI 서버는 영상 품질이 정상이고 모델 판정이 OK이므로, **'규칙 5'**를 적용하여 최종 판정(`final_result`)을 **`OK (ALL_CHECKS_PASSED)`**로 확정했습니다.  
> 아울러 표시된 HIGH 신뢰도 역시 영상 품질이 정상일 때 서버 규칙이 부여하는 상태값(`decision_confidence`)이며, 통계적으로 보정된 확률이 아닙니다.  
> 
> 여기서 가장 중요한 아키텍처 원칙이 있습니다.  
> 이 판정은 서버가 소유하며, **이후 호출되는 Gemini Agent는 이 검사 결과를 단 1글자도 변경할 수 없습니다.**"

---

### 4. Gemini의 근거 기반 진단 요약 (0:55 ~ 1:20)
*(상단 네비게이션에서 **[3. Gemini 진단 요약]** 칩을 클릭합니다)*

> "이제 우측의 AI Agent 영역을 보시겠습니다.  
> 백엔드 AgentService는 `gemini-3.8-flash` 모델을 통해 E2E 진단을 완료했습니다.  
> 
> 모델이 작성한 진단 요약문을 직접 읽어보겠습니다.  
> **'기록된 모델 판정과 종합 판정은 OK입니다. 실제 무결점 제품을 보증하지 않습니다.'**  
> 
> 보시다시피 모델은 판정 결과를 정확히 서술하면서도, 정상 판정이라고 해서 실제 결함이 0%임을 뜻하지 않는다는 산업 안전 가이드를 철저히 준수하고 있습니다.  
> 또한 양품 검사이므로 근거 없는 고장 원인 가설을 지어내지 않고 `possible_causes`를 **빈 배열(0건)**로 정확히 처리했습니다."

### 5. Evidence ID 및 JSON Pointer 결정적 검증 (1:20 ~ 1:45)
*(상단 네비게이션에서 **[4. Evidence 검증]** 칩을 클릭한 뒤, **`근거 참조: ["F0003"]`** 버튼을 클릭합니다)*

> "VisionInsight 신뢰성의 핵심인 **Evidence 검증 메커니즘**입니다.  
> **Gemini가 검사 기록 조회를 요청하면 서버가 Python 도구를 실행하고 `E0001`이라는 Evidence ID를 부여합니다. 이후 Gemini의 관측 사실이 해당 도구 결과와 일치하는지 서버가 검증합니다.**  
> 
> 화면의 표처럼, 모델이 주장한 6개의 관측 사실(F0001~F0006)은 `/data/final_result`와 같은 **정확한 JSON Pointer 경로**를 통해 실제 도구 반환값과 서버 메모리에서 1:1 결정적 비교를 거쳤습니다.  
> 버튼을 눌러 확인해 보면, 권장 조치가 가리키는 `F0003` 팩트가 서버의 실제 최종 판정인 `final_result: OK`와 완벽하게 연결되어 서버 검증을 100% 통과했음을 확인할 수 있습니다."

> 이상으로 VisionInsight의 근거 기반 AI 진단 데모 시연을 마치겠습니다. 감사합니다."

## 💡 발표자 Q&A 원포인트 팁

- **Q: 데모에서 실제 Gemini API를 호출하고 있는 건가요?**  
  **A:** "아닙니다. 본 화면은 실제 개발 서버에서 FastAPI ASGI 엔드포인트와 Gemini 실서버를 통과하여 기록된 정제된 실측 데이터를 시각화한 독립형 정적 데모입니다. 발표 현장의 네트워크 불안정 및 유료 API 호출을 방지하기 위해 오프라인 재생 방식으로 설계되었습니다."

- **Q: 상단의 JSON 복사는 전체 원본 응답인가요?**  
  **A:** "아닙니다. 발표 데모 화면 렌더링에 사용된 핵심 필드(검사 결과, AI 진단 요약, 관측 사실, 권장 조치, 한계 등)만 선별한 **데모용 주요 필드 축약 JSON 객체**입니다."

- **Q: 판정 신뢰도 HIGH는 AI가 100% 확신한다는 뜻인가요?**  
  **A:** "아닙니다. 영상 품질이 NORMAL이고 결함 탐지가 완료되었을 때 서버 규칙이 부여하는 상태값(`decision_confidence: HIGH`)이며, 통계적으로 보정된 결함 확률(Probability)이 아닙니다. 따라서 4대 한계 고지에도 '규칙 기반 HIGH 신뢰도는 보정된 확률이 아님'을 명시하고 있습니다."

- **Q: 이상 점수가 임계값보다 낮은데 왜 무결점을 보증하지 않는다고 하나요?**  
  **A:** "PatchCore 모델은 비지도 이상 탐지 특성상 테스트셋 기준 재현율이 약 50.79%이며 미세 결함 미탐 한계가 존재합니다. 따라서 임계값 미만 판정은 '현재 모델이 이상을 감지하지 못함'을 뜻할 뿐, 물리적 무결점의 증거가 아니므로 안전상 명확히 고지하고 있습니다."

- **Q: F0003 버튼을 누르면 무엇이 일어나는 건가요?**  
  **A:** "모델이 권고한 `CONTINUE_MONITORING` 조치가 어떤 관측 근거에 기반했는지를 추적하여, 서버가 부여한 도구 영수증 `E0001`에서 가져온 `/data/final_result = 'OK'` 행을 하이라이트하는 결정적 근거 추적 시연입니다."
