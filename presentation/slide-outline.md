### [Slide 3] 시스템 아키텍처: Vision, Decision, Agent의 명확한 역할 분리
- **슬라이드 제목:** 시스템 아키텍처: Vision, Decision, Agent의 명확한 역할 분리
- **핵심 메시지:** "비전 모델, 결정론적 규칙 판정, 생성형 AI Agent의 책임을 엄격히 분리하여 안전성과 설명력을 동시 달성합니다."
- **화면 구성 (3개 수평 계층 다이어그램):**
  - **Layer 1: Vision 계층**  
    900×900 이미지 수신 및 영상 통계(평균 밝기, 표준편차) 계산 ➔ 품질 상태 평가 (NORMAL, WARNING_LOW_BRIGHTNESS, ERROR) ➔ PatchCore ResNet-18 특징 추출 및 이상 점수 산출 (개발 환경 CPU 평균 42.53ms)
  - **Layer 2: Decision 계층 (서버 규칙)**  
    규칙 기반 종합 판정 (우선순위 1~6단계 규칙) ➔ REINSPECT 분리 판정 (영상 품질 경고 시 서버의 최종 판정을 REINSPECT로 분류하여 결함 판정과 구분) ➔ 판정 불변 원칙 (서버가 확정한 판정값은 이후 Agent가 절대 변경할 수 없음)
  - **Layer 3: Agent 계층 (Gemini AI)**  
    Function Calling으로 검사 결과 및 품질 메트릭 사후 조회 ➔ 추정 원인 가설, 현장 점검 권고, 안전 한계를 구조화하여 제안 ➔ 모델의 모든 관측 사실(Fact)을 서버 메모리에서 1:1 결정적 검증
  - *(하단 강조 배너: "💡 아키텍처 원칙: Vision(고속 추론) → Decision(서버 판정 확정) → Agent(사후 원인 진단)으로 책임을 분리하며, 현재는 서버 판정값을 확정하는 프로토타입으로 실제 물리적 PLC·컨베이어 제어는 수행하지 않습니다.")*

### [Slide 4] Vision 계층 성능: PatchCore 이상 탐지 실측 결과
- **슬라이드 제목:** Vision 계층 성능: PatchCore 이상 탐지 실측 결과
- **핵심 메시지:** "불량 데이터 없이 정상 180장만으로 고속 추론을 구현했으나, 미세 결함에 대한 미탐 한계가 존재합니다."
- **화면 구성 (좌측: 핵심 성능 지표 / 우측: 혼동 행렬 및 분석):**
  - **좌측 (핵심 성능 지표, 83장 테스트셋):**
    - [Image AUROC] **0.8286**
    - [정밀도 Precision] **100.0%** (근거: TP=32, FP=0 / 해당 83장 표본 기준)
    - [재현율 Recall] **50.79%** (근거: TP=32, FN=31 / 미탐 31건 발생)
    - [고정 임계값] **34.1442** (독립 정상 검증 데이터 29장의 통계 기반: $\mu + 3\sigma = 34.1442$)
    - [CPU 단일 추론 시간] **평균 42.53ms** (개발 환경 x86_64 CPU 단일 이미지 평균 실측치, T01: 41.3ms, T03: 42.7ms)
  - **우측 (혼동 행렬 및 엔지니어링 분석):**
    - 진양성 (TP): 32건 (실제 결함을 이상 NG로 정확히 탐지)
    - 위양성 (FP): 0건 (정상 제품을 결함으로 오판정하지 않음)
    - 진음성 (TN): 20건 (정상 제품 20장을 양품으로 정확히 판정)
    - 위음성 (FN): 31건 (미세 파손/오염 등 31건 미탐지, 재현율 50.79%)
    - *(하단 고지: "💡 시사점: FP 0건으로 과검은 없으나, 미탐(FN 31건) 한계가 존재하므로 모델의 OK 판정이 실제 무결점을 보증하지 않는다는 점을 안전 가이드에 필수 명시함.")*

### [Slide 5] Decision 계층: 대표 판정 규칙 4가지와 REINSPECT 분류
- **슬라이드 제목:** Decision 계층: 대표 판정 규칙 4가지와 REINSPECT 분류
- **핵심 메시지:** "조명이 어두워졌다고 불량품이 아닙니다. VisionInsight는 오판을 방지하고 재검사(REINSPECT)를 지시합니다."
- **화면 구성 (4대 대표 규칙 카드 + 핵심 원칙):**
  - Rule 1: 파이프라인 실패 ➔ `ERROR` [`INSPECTION_FAILED`] (조건: status == 'FAILED' / 영상 로드/포맷 오류 등 검사 파이프라인 실패 시 ERROR 처리 및 오류 이벤트 기록)
  - Rule 2: 영상 품질 경고 ➔ `REINSPECT` [`IMAGE_QUALITY_WARNING`] (조건: image_quality_status != 'NORMAL' / 조도 저하(T03) 시 모델이 OK여도 제품 결함(NG)과 구분하여 '재검사 필요'로 분류)
  - Rule 4: 제품 이상 탐지 ➔ `NG` [`PRODUCT_ANOMALY_DETECTED`] (조건: 품질 NORMAL and result == 'NG' / PatchCore 이상 점수가 임계값을 초과하여 모델 NG로 판정되고, 서버 규칙에 따라 최종 NG로 분류)
  - Rule 5: 정상 검사 통과 ➔ `OK` [`ALL_CHECKS_PASSED`] (조건: 품질 NORMAL and result == 'OK' / 영상 품질 NORMAL이고 이상 점수가 임계값(34.1442) 이하인 정상 제품 T01)
  - *(하단 강조 배너: "💡 대표 판정 규칙 4가지 (전체 6개 규칙 중 우선순위 반영): Rule 3(모델 미수행 ➔ DEFECT_DETECTION_UNAVAILABLE), Rule 6(미정의 조합 ➔ UNKNOWN_STATE_COMBINATION) 포함. REINSPECT는 물리적 폐기/격리 제어가 아닌 서버 판정 상태 분류입니다.")*
- **시간:** 2구간 (Slide 4~5 합계 2분 중 약 1분)

### [Slide 6] AI Agent: Gemini Function Calling 기반 정밀 조사 체계
- **슬라이드 제목:** AI Agent: Gemini Function Calling 기반 정밀 조사 체계
- **핵심 메시지:** "Gemini가 직접 함수를 실행하는 것이 아니라, 도구를 제안하면 서버가 안전하게 실행하여 전달합니다."

- **핵심 메시지:** "도구 실행 영수증과 JSON Pointer가 서버 실제 값과 일치해야만 보고서가 수락됩니다."

### [Slide 8] 기술적 문제 해결: Gemini 구조화 출력 호환성 개선
- **슬라이드 제목:** 기술적 문제 해결: Gemini 구조화 출력 호환성 개선
